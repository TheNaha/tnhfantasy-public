# Codebase audit — 2026-10-03 (second pass)

Supersedes `docs/audit-2026-10-03.md` for everything it marks fixed. Read this
with `docs/STATUS.md`.

Five parallel read-only passes — backend architecture, frontend architecture,
infra/deploy/providers, **live feature verification by driving the running
stack**, and remediation by four agents working on disjoint file sets. Every
claim below is either reproduced on the live stack or read at a cited
`file:line`.

Baselines measured before any change: backend **2824 passed / 8 skipped**
(875 s), frontend **1352 passed / 146 files**, providers **793 passed /
4 skipped**. After: backend **2953 / 8**, frontend **1464 / 157**, providers
**833 / 4**. `npm run lint` **0 errors / 12 warnings** (unchanged),
`ruff check .` clean in both Python trees.

---

## 1. Executive summary

The consolidation itself was **not** the problem, and again there are **no
stubs**. What "many functions are literally non-functional" turned out to mean
is narrower and worse than it looks, and it is worth being precise about
because the shape repeats:

> **A control that renders, persists, and reports success while the value goes
> nowhere.** Not one instance — a family, on both sides of the wire.

The two that a user actually hits:

1. **Send a chat message, get "Ilse Vondt is thinking…" forever.** The
   submitter learns its job id from the HTTP response; the terminal WebSocket
   event arrives first. Measured: `job.failed` at t=6174 ms, the POST returning
   200 at t=6230 ms. The failure was handled against an empty store, then the
   response inserted a placeholder whose only removers had already fired. A
   reload was the only escape. **All seven** insertion sites share the shape.
2. **The Advanced Workflow page cannot build a workflow at all.** It asked
   whichever provider sorted first — `direct_url`, registered `enabled=false`.
   The proxy returned HTTP **200 carrying an error body**, so the hook cached
   the error object as the node definitions for 24 hours and rendered a palette
   with one category literally named `unknown`.

And the most consequential finding was not in the application code at all: the
event-loop invariant test that is supposed to prevent blocking routes was
**blind**, because one entry in its search path pointed at a directory that does
not exist. A guard that cannot see the code is not a guard.

## 2. P0 — fixed, each pinned by a test confirmed to fail when reverted

### 2.1 A failed chat reply left a permanent "thinking…" placeholder

`src/hooks/useStreamingJobs.js` · `src/contexts/ChatWorkspaceContext.jsx:541` ·
`src/hooks/useChatStreaming.js:186-206`

A submitter learns its job id from the HTTP *response*. The terminal event
(`job.completed` / `job.failed` / `job.cancelled`) can arrive first. Measured on
the live stack, single send:

```
t=6123ms  WS recv  job.created  id=697afdc5 status=pending
t=6174ms  WS recv  job.failed   id=697afdc5        (20 ms later)
t=6230ms  HTTP POST /messages -> 200 {"job_id":"697afdc5"}
```

`unsubError` ran `clearStreamingJob` against a store that had nothing in it —
a no-op. Then `onSuccess` inserted `{text:'', status:'running'}` for a job
whose terminal events had all already fired. The UI showed the character
thinking at t+5 s, +15 s, +30 s, +60 s, +90 s, +120 s and **+150 s**, the
composer stayed enabled, no error was attached to the message, and the turn was
silently lost — `GET /api/v2/chats/{id}/messages` confirmed the user message
persisted and no assistant message was ever written.

**Fix, in the primitive rather than at the call sites.** `clearStreamingJob` now
records the job id in a bounded module-level settled set (200 entries, FIFO) and
`setStreamingJob` refuses to insert a settled id. All seven insertion sites are
covered because they all go through the store, and a new terminal handler
cannot forget to call it. The set is module state on purpose: it must be
readable synchronously from outside React, and it is worthless after a reload.

`src/test/streamingJobTerminalInvariants.test.jsx` — 7 tests, **6 fail** when
the fix is reverted (the seventh is the control).

### 2.2 The event-loop invariant test could not see most of the codebase

`tests/test_event_loop_invariant.py`

Three blind spots, all of which make the guard pass routes it should fail:

- `SEARCH_DIRS` contained `SRC_DIR / "infrastructure"`, where `SRC_DIR` is
  `backend_v2/api` — i.e. **`backend_v2/api/infrastructure`, which does not
  exist**. `backend_v2/infrastructure/` and `backend_v2/core/` were never
  indexed. `_function_index` skips missing directories silently.
- The resolver scored an **unresolvable** awaited name as "a genuine
  suspension" and passed the route. So *every* await of a repository method or
  a `core/` helper was waved through.
- `depth > 3` truncated the walk at exactly the depth of the real service facade
  chain (`ModelServiceV2` → `ModelCivitaiSyncService` → `ModelDownloader`).

Note for the next reader: **`asyncio.Lock.acquire()` on an uncontended lock does
not yield.** `EventBus.publish` (`core/events.py:308`) and
`worker_registry._get_live_worker` (`infrastructure/worker_registry.py:268`) are
`async` with no real suspension, which is why several flagged routes were not
actually blocking.

**Fixed:** all four directories indexed, `depth` replaced by a cycle-safe
visited-set BFS, and a new guard test asserts every `SEARCH_DIRS` entry exists
and contains Python — the file already had two such guards and this one was
missing. Six newly-visible offenders converted to worker-thread `def` handlers
or `asyncio.to_thread`, each registered in `SYNC_CHAINED` with its service
method named. `api/routes/jobs.py:151 create_job` was **deleted** from the
register — it is genuinely fixed now (`JobService.create_job` awaits
`asyncio.to_thread`). Six more entries stated a reason that was no longer true
and were rewritten.

Verified non-vacuous: removing `infrastructure/` from `SEARCH_DIRS` makes the
new guard fail.

### 2.3 Two batch endpoints: unbounded input, a DB write per element on the event loop, HTTP 200 on partial failure

`api/routes/models/provider_sync.py`

- `BatchUpdateRequest.updates` had no `max_length` and `batch_update_status`
  never called `require_batch_size`, though the codebase has that guard and
  applies it at three other batch endpoints. `except Exception: failed += 1`
  then `return {"updated": …, "failed": …}` — **HTTP 200 on partial failure**.
- `receive_batch_sync_progress` passed a deliberately empty path list to
  `repo.get_file_ids_by_storage_paths([])`. `_iter_file_model_paths` only adds a
  `WHERE` when the list is non-empty, so `[]` materialised the **entire model
  library** via a two-join `select(ModelFile, ModelVersion, ModelV2).all()`,
  per request, plus a Python dict comprehension and a per-path `.split('/')`.

Both bounded, both moved off the loop, the partial-failure shape made explicit.
`tests/test_batch_endpoint_bounds.py`.

### 2.4 `/advanced` picked a disabled provider and cached the failure for 24 hours

`src/pages/AdvancedGenerator.jsx:154` · `src/hooks/useObjectInfo.js`

`providerId={providers[0].id}` — the first provider in the list, not the first
*enabled* one. The live list starts with `direct_url`, `enabled=false`.

| | measured |
|---|---|
| `GET /api/nodes/object_info?provider_id=direct_url` | **30.02 s**, three consecutive calls (so not a cold start) |
| response | **HTTP 200** with `{"status":"error","message":"Failed to query ComfyUI: ","code":502,"success":false}` |
| for contrast, `provider_id=modal-zetsuke` (enabled) | answers in 43 s with real node definitions |

Because the status was 200, `useObjectInfo` could not tell the payload from a
success, so it wrote the **error object to IndexedDB** and returned it —
`staleTime` 24 h with `refetchOnMount: false`. `NodeRegistry` then built a
palette from its six keys, none of which has a `.category`, rendering one group
named `unknown`. Observed: sidebar text `unknown 6`, **one** button, zero
`.react-flow__node` elements, and the only route in a 35-route sweep that never
reached `networkidle`. The `if (error)` branch was unreachable on that path.

**Fixed** both halves: an enabled provider is preferred (falling back to the
first so the page is never blank while one is being switched on), and
`useObjectInfo` now rejects an error envelope before it can be cached — or
served back from a cache a pre-fix build wrote.

### 2.5 One invisible-but-tappable **destructive** control survived the hover-reveal fix

`src/components/generator/ControlNetSection.jsx:52-53` · `src/index.css`

The 2026-10-03 pass added an `@media (hover: none)` rescue forcing
`opacity: 1` on hover-revealed controls, because they are laid out,
hit-testable and invisible on a touch device — a real CDP tap was delivered to
an invisible button. That rescue block was a hand-maintained list of class
names, and the list was **incomplete**: `group-hover/card` was missing while
`chat-row` and `menu-item`, which no source file has ever used, sat in it
looking load-bearing.

Result: the ControlNet **delete** button computed to
`opacity: 0; pointer-events: auto; visibility: visible` on any touch device —
invisible, and it deletes a ControlNet on tap. Full enumeration: 38 hover-reveal
sites, 37 covered, 1 not.

**Fixed** the block, and — because a hand-maintained list is the actual defect —
`src/test/hoverRevealInvariants.test.js` now reads every `group-hover/<name>`
out of `src/**` and fails if a name is missing, *and* fails if the block carries
a name nothing uses. 5 tests; verified to fail with `card` removed.

### 2.6 A labelled `<select>` with three vocabularies, which renders blank

`src/pages/Settings.jsx` · `src/store/settingsStore.js` ·
`src/pages/Dashboard.jsx` · `src/components/dashboard/DashboardHeader.jsx`

`ui.defaultViewMode` was doing two incompatible jobs: it was the *live* gallery
view **and** the persisted *default*. Three files had three vocabularies:

| writer | values |
|---|---|
| `Settings.jsx` `<option>`s | `grid`, `list`, `feed` |
| `DashboardHeader` buttons | `grid`, `list`, `feed`, **`timeline`** |
| `Dashboard` toggle | `grid`, **`session`** |

`timeline` and `session` were writable with no matching `<option>`, so a
`<select value="session">` rendered **blank**, and picking any value from it
silently switched the gallery out of the session view the user was in. And
because it was the same key, the "default" was overwritten by the first gallery
interaction of every session — it could not describe a default at all.

**Fixed** by splitting the concepts: `GALLERY_VIEW_MODES` is now one exported
vocabulary the buttons and the options are both derived from; `ui.viewMode` and
`ui.gridColumns` are the live values (`null` = follow the default, which is what
an upgrading install gets); `defaultViewMode` / `defaultGridColumns` are only
written from Settings. The select's value is coerced into the vocabulary before
it reaches the DOM, so a corrupt persisted value can no longer render it blank.

### 2.7 `generatorStore.autoApplyModelSettings` was permanently `true` with no control anywhere

`src/store/generatorStore.js:168,225` · `src/pages/Settings.jsx`

Selecting any checkpoint with recognizable metadata overwrote `steps`, `cfg`,
`sampler`, `scheduler`, `width`, `height` and `clipSkip` from
`BASE_MODEL_SETTINGS`. Full-repo grep for the setter: the definition, plus its own
unit test. **Zero UI references.** The field, the setter and the test all
existed; only the control was missing.

**Fixed** by rendering the toggle in Settings → Generator (the setter and field
were already correct). Same shape as the deleted `models.autoRemoveDownloads`
switch from the first pass — the recurring lesson is in §7.

## 3. P1 — fixed

### 3.1 A transient embedding failure **destroyed** a good vector

`api/routes/world_vault/memories.py:243-250`. Inside `update_memory` on an
**existing** row: `except Exception: mem.embedding = None`, committed at `:250`.
One rate-limit or provider 503 overwrites a previously-good vector with NULL, and
semantic recall for that memory is gone until someone runs the manual reindex
route. Now left untouched on failure and logged.

### 3.2 A Docker failure reported "stopped"

`services/provider_lifecycle_service.py:106-113`. `except Exception` around a
Docker client call catches daemon-unreachable, permission denied, TLS failure and
missing context — all rendering as *"the container is stopped."* Now
`docker.errors.NotFound` → stopped, everything else → `ServiceUnavailableError`
with an explicit degraded signal, matching the `filesystem_fallback` precedent.

### 3.3 `commit()` **and** `rollback()` inside a loop

`services/world_integration_service.py:503-520`. A commit per image, and a
rollback not scoped to the failed row — it discarded every sibling row pending
on that session. If image 3 of 4 failed, the job still read COMPLETED with 3 of
4 images in the gallery but 3 of 4 in the transcript. Now `add_all`, one commit,
one rollback in an outer `except`.

**Five other `commit()`-per-chunk sites were investigated and left alone** —
`memories.py:159`, `rag_pipeline.py:440`, `asset_metadata_index.py:564`/`:734`,
`tag_service.py:401`. Measured: 9 rows in 3 chunks cost 7 refresh `SELECT`s clean
vs 16 with a rollback at chunk 1. Bounded, not data loss, and each is a
documented keyset-resumable batch job whose contract *is* commit-per-chunk.

### 3.4 `reconciliation.failed` was emitted by the backend and handled nowhere

`api/routes/providers/reconciliation.py:141` emits it; it is in the enum **and**
in `TERMINAL_EVENT_TYPES`; the frontend had no constant and no subscriber. A
worker failure left the provider card reading "reconciling" with no toast and no
error until a manual refetch, while the database already held the failed status.
Its sibling `provider.deploy_failed` *was* handled, so this was an oversight.

### 3.5 `model.sync_progress` was emitted on every download heartbeat and dropped

`api/routes/models/provider_sync.py:322`. The worker POSTs `progress` (0-100)
plus `size_bytes` on every heartbeat. A frontend constant existed; no subscriber
did. Now surfaced as a progress toast keyed by provider+model.

### 3.6 The whole `download.*` event family was a contract on both sides, implemented by neither

Four enum members plus `emit_download_event` had **zero** producers in production
code and **zero** subscribers, while `App.jsx` carried three matching handlers
under a comment describing a feature ("download progress") that did not exist.
Model-download status is polled. Leaving this was the only wrong option, so it
was **removed from both sides** rather than left to look like push-based
progress already works.

`src/test/eventContractInvariants.test.js` now asserts three rules over both
trees: every backend `EventType` has a frontend constant with the same wire
value, every one has a producer, and every one has a subscriber. It is
demonstrably non-vacuous — it caught §3.5 and §3.6 unprompted.

### 3.7 Three dialogs outside the shared contract

`useEscapeKey.js:9-17` documents the hazard exactly: every handler is a
`window` listener in the bubble phase, so `stopPropagation()` cannot disarm
siblings, and a handler that ignores `defaultPrevented` closes the dialog
*underneath* the one on screen.

- `GlobalCommandPalette.jsx` installed its own listener and called
  `preventDefault()` but not `stopPropagation()` — one Escape with the palette
  open over a dialog closed both. Escape now goes through `useEscapeKey`; the
  arrow/Enter navigation keys keep their own listener.
- `SessionPanel.jsx` declared `aria-label="Collections"` (copy-paste residue,
  otherwise character-for-character identical to `CollectionsPanel`) and called
  `useEscapeKey` nowhere. It also turned out to already have a *hand-rolled*
  Escape listener, which had to be removed rather than added to.
- `PromptForm.jsx` was a `fixed inset-0` overlay with no backdrop close, no
  Escape, no `role="dialog"`. Now on `ModalOverlay`.

⚠️ `ModalOverlay`'s own `role` was **not** touched — a previous attempt broke 8
tests and was reverted.

### 3.8 A dead share link silently dumped you on the home page

`src/pages/StoryReader.jsx`. A 404 token redirected to `/roleplay`, so someone
clicking a dead shared link was shown a workspace they never asked for, with no
message. Now an explicit invalid/unpublished state.

### 3.9 `ChatWorkspaceContext` published `selectChat` with no matching dependency

`src/contexts/ChatWorkspaceContext.jsx`. `selectChat` was a context key absent
from the `useMemo` dependency array — safe only because
`useCallback([activeChatId, navigate])` means its identity moves exactly when
`activeChatId` moves, and `activeChatId` *is* a dependency. The moment it gained
a dependency of its own, consumers would have held a stale closure.

Worse, `useChatWorkspaceData.js` carried a comment saying `worlds` was
"deliberately NOT in the contextValue memo". It was in **both** the key list and
the dependency array, and `ChatContextPanel` genuinely reads it. The false
comment was the defect: it invited the next reader to "restore" the exclusion by
deleting a dependency the panel needs.

`src/test/chatWorkspaceContextMemo.test.js` parses both lists and asserts they are
the same set — 6 tests, verified to fail with `selectChat` removed.

### 3.10 The published-story **export** bypassed the published-**read** redaction

`api/routes/world_vault/stories.py`. `GET /published/{token}` builds a
deliberately narrowed projection — no internal ids, no chapter `beats`, no
lorebooks. Its sibling `GET /published/{token}/export` resolved the same token and
returned `export_story` unfiltered, including all three. The token is a *share
link*; `beats` is the author's private planning outline, which is exactly what
the projection was written to withhold. `export_story` now takes
`published: bool = False`; `tests/test_published_story_redaction.py` asserts the
published export is a **subset** of the published read.

### 3.11 `downloads.py` acted destructively on `indeterminate`

`provider_core/provider_core/downloads.py:910`. `validation.py:64-68` states the
contract: *"A caller that can act destructively on `invalid` MUST check
`indeterminate` first."* Four callers honour it; this one deleted the temp file
**and every resume slot**, so one transient gcsfuse read fault threw away resume
progress on a 7 GB download.

The subtlety: the generic `except` sweeps the temp file on any raise, so "don't
delete" had to become **"re-park the partial"** or the bytes survive where no
attempt will find them. A test proves the *next* attempt resumes, not merely that
a file remains.

### 3.12 `scripts/preflight.sh`'s provider check was dead

`scripts/preflight.sh:118,122` curl `http://localhost:8002/api/v2/providers/`.
The 2026-10-03 port removal means that is now `000` — so the check added
specifically so "5 of 6 providers disabled" could not cost another afternoon could
never fire again, and its fallback was `note`, not `bad`, so preflight exited 0
reporting nothing. Now reads from inside the container and treats an unreachable
backend as a failure. It fires: **"5 of 6 registered providers are switched
off."**

### 3.13 `COMFY_DATABASE_URL` was silently discarded

`infrastructure/database.py:90-95`. The comment said an explicit
`COMFY_DATABASE_URL` always wins; two lines below, any **non-`postgresql`** value
— i.e. the documented SQLite case — was replaced by the `POSTGRES_*`-assembled DSN
whenever `POSTGRES_HOST` was set, which compose always sets. Live proof: the
container held `COMFY_DATABASE_URL=sqlite:///./data/comfy.db` while the live data
was in Postgres.

**Note:** the straightforward fix (make the env var authoritative) was tried and
**broke the running stack** — it moved the backend onto a 66-row SQLite file and
began 500-ing every provider route. `POSTGRES_*` is authoritative for this
deployment, so the shipped fix keeps that and **logs the discard by name at
boot**; the silence was the actual defect. See §6.

## 4. P2 — consolidation, duplication, dead weight

### 4.1 30 sites hand-wrote the `world_vault` query-key namespace

`constants/queryKeys.js` exports `buildQueryKey()` and is imported by 26 files —
the most-shared key factory in the app — while 30 sites across 15 files hardcoded
`['world_vault', 'chats']` instead, so it could not be renamed in one place. The
load-bearing one was `useChats.js:16`, which hardcoded the string *and* built the
system-prompt key through the factory one line later. All 30 converted, each
byte-verified; `src/test/vaultQueryKeyInvariants.test.js` strips comments, sweeps
`src/**`, and names the remaining to-dos by file and line.

The 6 unreferenced `QUERY_KEYS` members were **deleted**, not renamed:
`buildQueryKey` always prepends `world_vault`, so every one of them could only
ever build a key matching nothing, and four collided *by name* with real
non-vault namespaces (`['settings_config']`, `['statistics','detailed',…]`,
`['providers-page','providers']`, `['gallery',…]`).

### 4.2 Two incompatible exports named `useTagVocabulary`

`useGallery.js:125` took `(prefix = '')`; `useAssetTags.js:32` took
`({prefix, q, limit})`. Both were live, both behind byte-identical api wrappers
for one endpoint. Both import sites read
`import { useTagVocabulary } from …`, so passing a string to the object-signature
version destructured it into `{0:'c',1:'h',…}` → `prefix`/`q`/`limit` all
`undefined` → the query silently became the **unfiltered** vocabulary with no
error. One implementation survives.

### 4.3 Three CivitAI searches, three cache keys, one endpoint — and four autopopulate mutations

`useCivitaiSearch.js` (canonical), `CivitaiSearchModal.jsx` (hand-rolled
`useQuery`, key `['civitaiSearch',…]`), `AutopopulateSelector.jsx` (raw `api.get`
+ `useState`, **no cache at all**), plus four hand-written mutations of
`POST /models/{id}/autopopulate` each owning its own invalidation. Now one
canonical hook plus `useCivitaiSearchPage()` and `useAutopopulateModel()`.

### 4.4 84 of 86 `queryFn`s threw away the `AbortSignal`

`api/client.js` accepted and merged `signal` correctly; almost nobody passed it.
Cost is concrete on the search pages keyed per keystroke. Two real defects found
on the way:

- A caller's signal **replaced** the client's 30 s timeout rather than composing
  with it, so naively threading signals everywhere would have silently removed
  the timeout from the whole app. Now one controller for both reasons to stop,
  with a `timedOut` flag separating them.
- When a caller *did* pass a signal, `abortTimeout` was `undefined`, so an abort
  surfaced as `ApiError(msg, 0)` — a real error to React Query — instead of a
  cancellation.

### 4.5 LIKE patterns built from user input, unescaped — 27 sites, 10 files

A search for `100%` or `a_b` silently widened the match set. Bound as a
parameter, so not injection — a correctness defect. One shared escape helper
(`core/sql_search.py`) plus a verified `ESCAPE '\'` clause at 17 call sites
across 13 files. Verified on both engines (SQLite renders `LIKE ? ESCAPE '\'`;
Postgres parses `'\'` as one backslash with `standard_conforming_strings`).
An AST guard fails if escaping is applied without the clause.

### 4.6 Local time was building a UTC-stamped date partition

`infrastructure/image_processor.py:60` and
`services/asset_reconciler.py:646-648,655-657` used naive `datetime.now()` to
build the `YYYY/MM/DD` output partition, while `Asset.created_at` is UTC. An
image made at 23:30 local (UTC+2) is filed under **tomorrow's** local directory
with a `created_at` of 21:30 today, so the directory tree and the gallery date
rail disagree for every image in the offset window around local midnight. Six
sites now use `datetime.now(timezone.utc)`.

**Correction to the first pass's audit**, which had this backwards: it claimed
`job_service.py:836` "compares `datetime.utcnow()` against a timezone-aware
column". `jobs.created_at` is **naive on both backends** (SQLite `DATETIME`,
Postgres bare `TIMESTAMP`), so `utcnow()` is the consistent choice there and was
left alone — as was `scheduler.py:216`, where APScheduler's `IntervalTrigger` is
local-time by contract.

### 4.7 Dead code, removed

- The `download.*` event family (§3.6).
- `generatorStore`: `lastAppliedModelType` (3 references, all writes, zero reads,
  persisted forever), `setControlnets`, `clearMask`, `applyModelSettings`.
  `applyModelSettings`'s three tests were **rewritten, not deleted** — as
  `it.each` over four architectures through the live `setSelectedCheckpoint` path,
  which previously had no coverage of its own.
- 6 unreferenced `QUERY_KEYS` members (§4.1).
- `GlobalCommandPalette`'s `NAV_ITEMS` had a hand-written `Worlds` row
  colliding with the one `EXPERT_TOOLS` contributes. Rows are keyed by
  `${kind}:${label}`, so that was a duplicate key *and* a duplicate entry.
- `_ensure_index` (`migrations/steps.py:3443`) was dead *because of* a
  duplication — its logic is re-implemented as a nested closure in
  `_migration_080`.

### 4.8 `useProvidersPageData` returned a fresh `[]` every render while loading

`providersQuery.data || []` inside an **unmemoized** object literal, feeding 8
call sites — one of which puts it in a `useMemo` dependency, so that memo
recomputed on every render for the whole time the request was outstanding. Now a
module-level `EMPTY_PROVIDERS` + `useMemo`, following `useFavorites.js`.

## 6. Corrections to the first pass's audit

Four of its claims did not survive re-measurement. Each is recorded because a
report that hides its own error rate is not usable:

1. **"0 invisible-but-tappable controls across 25 routes."** That sweep could
   not reach `ControlNetSection`'s delete button — the section only exists once a
   ControlNet is added. Still broken; fixed in §2.5. And the rescue block's own
   comment claimed it was "written against the escaped utility names so a newly
   added hover-reveal is covered by the same rule instead of needing to be
   remembered here." It was not.
2. **"0 of 48 `queryFn`s consume the AbortSignal."** It is **84 of 86**.
3. **"ChatWorkspaceContext exposes 171 keys."** It is **170**, unique.
4. **"The worst naive-datetime site is `job_service.py:827`."** See §4.6 — it is
   the one site that was correct.

And two of its *counts* were low rather than high: `key={i}` on 41 lists (51),

## 7. Where the root causes are

Ranked by defects retired per fix, not by severity.

1. **A primitive that supplies part of a contract makes adoption optional.**
   `useStreamingJobs` supplied insert and remove but not *terminal-ness*, so all
   seven submitters could lose a race. `useObjectInfo` supplied a fetch but not a
   payload check. `useProvidersPageData` supplied data but not a stable empty
   value. `buildQueryKey` supplied the key but not enforcement. `ModalOverlay`
   supplies Escape but not focus. `useProvidersPageData`'s siblings supply
   `onError` for 6 resource families and not the other 85 mutations.
   The rule that retires the family: *a primitive either owns the whole contract
   or none of it.*
2. **A contract on both sides, implemented by neither.** `download.*` existed as
   a backend enum, a backend helper, four frontend constants and three frontend
   handlers, with no producer anywhere. `ui.defaultViewMode` existed as a setting
   with an `<option>` list that did not match its own value space. Both look
   finished. §3.6 and §2.6 are the same defect on the two sides of the wire.
3. **A guard that cannot see the code is not a guard.** The event-loop invariant
   test indexed a directory that does not exist and scored every unresolvable
   await as a pass. The hover-reveal rescue listed class names by hand. The
   settings-key guard was previously defeated by a *comment* mentioning a
   deleted key. Each is now generated from the thing it constrains.
4. **Testing is enumerated, not invariant-based.** Every fix in this document
   ships with a test that asserts the **rule**, and every one was confirmed to
   fail when its fix was reverted. That is the only reason §2.1–§2.7 will not be
   rediscovered by the next pass.
5. **Config and docs that silently disagree with the code.** `preflight.sh`
   checking a port that no longer exists; `docker-compose.yml` still injecting a
   variable the audit had deleted; `docs/deployment.md` telling the operator to
   bind 8002 to `0.0.0.0` — advice that would have reopened the exact hole the
   previous pass closed.

## 8. Still open

Ordered by what they cost you.

1. **No LLM provider is enabled.** `GET /api/v2/llm/available-models` → `[]`.
   Every chat turn fails in 20–40 ms with `No available providers`. Until one is
   enabled, "send a message and get a reply" is non-functional on this stack —
   which is why §2.1 was invisible until it was found by reading the code rather
   than by using the app. `preflight.sh` now reports the count.
2. **`docs/api.md` is not drift-checked.** `STATUS.md:111` says it "is checked
   against `app.openapi()["paths"]`". **No test references `api.md`.** The 201/329
   coverage figure is unverified and almost certainly stale.
3. **`backend_v2/Dockerfile` and `frontend_v2/Dockerfile` are built by no CI
   workflow.** A `app-images` job has been added; the first CI run is the proof.
4. **Naive datetime columns.** The model layer writes timezone-aware datetimes
   into naive columns and relies on the driver to drop the offset. Correct today
   only because the container runs UTC. Needs a `TIMESTAMPTZ` migration.
5. **`asset_reconciler.py:661` writes unpadded date parts** (`2026/3/14`) where
   the writer emits `2026/03/14`. The legacy migrator creates a directory shape
   the writer never creates. Needs a file migration.
6. **12 unbounded list endpoints** (7 named by the first pass, plus
   `/characters`, `/voices`, `/collections`, chat export, prompts export) and
   eight spellings of pagination clamping.
7. **8 pagination-clamp implementations**, only one of which tells the caller
   their request was wrong; the other seven silently return a different page
   size than asked.
8. **17 dead `config.py` accessors**, with a divergent live reader of the same
   key at `services/job_queue.py:301` (`.get` + a `10**6` fallback, where the
   accessor would raise `KeyError`).
9. **`ModalOverlay` has no focus trap.** ⚠️ Do not touch its `role`.
10. **33 inline empty states** against one shared `EmptyState` that still has no
    error slot — which is *why* all 33 had to decide where errors go.
11. **17 confirmed backend routes with no frontend caller.**
12. **`tests/test_app_boot_smoke.py::test_lifespan_runs_every_declared_startup_phase`
    is flaky under full-suite load.** Observed failing twice and passing twice,
    including before this pass's changes; it passes in isolation and its own
    docstring documents the cause (real threads, 20 s poll, 2950 other tests
    hammering the same loop). Not fixed.
13. **`COMFY_DATABASE_URL` in your `.env`.** Delete it. It is inert, but it is
    the variable that produced finding §3.11 and the value the live container
    reports, which is what made that finding look like a live outage risk. The
    backend now logs the discard by name at boot, so the ambiguity is visible
    rather than silent — but the line should go.
