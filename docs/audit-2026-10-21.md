# Audit — 2026-10-21 (consolidation sweep)

Six parallel read-only passes over disjoint scopes: backend job system, backend
roleplay/agent pipeline, backend models/providers/engines, frontend generation
surfaces, frontend state/realtime, and a whole-tree cross-seam sweep. Every
candidate was traced to a caller and confirmed against the running stack
before it was accepted.

**Baselines before this pass** (measured, not quoted):
backend `3911 passed, 5 skipped` (368 s) · frontend `1978 passed` (218 files,
225 s) · `ruff check .` clean · `npm run lint` 0 errors / 3 warnings ·
`http://localhost:5174/` → 200.

**Headline.** The consolidation did not leave the tree broken. What it left is
**a set of controls that render, persist, report success and go nowhere** —
the exact shape every previous pass found. The most expensive one is that
**every Flux and AuraFlow generation is dead on all four guided surfaces**.

The tree is otherwise unusually clean: **0** never-imported frontend files,
**0** never-imported backend modules, ruff clean, eslint 3 warnings, 45
backend routes with no consumer.

Severity: **P0** breaks a feature outright · **P1** user-visible wrong
behaviour or a silent data/state failure · **P2** cost, waste, or an inert
control · **P3** cleanup.

## 1. P0 — Flux/AuraFlow generation is dead on every guided surface

**1.1 · `backend_v2/core/workflow_builder.py:85` — `GeneratorOptions.checkpoint`
is a non-Optional `str`, and the client sends `checkpoint: null` for every
UNET model.**

- `core/workflow_builder.py:85` `checkpoint: str = ""` — while its siblings on
  lines 86-89 (`unet`/`clip`/`clip2`/`vae`) are `str | None = None`. The
  asymmetry is the bug.
- `frontend_v2/src/hooks/useWorkflowBuilder.js:79` `checkpoint: isUnet ? null :
  selectedCheckpoint?.name`. `isUnetModel` is true for any model whose
  `base_model` contains "flux" or "aura"
  (`frontend_v2/src/utils/modelType.js:2-12`).
- `JSON.stringify` keeps the `null` (`frontend_v2/src/api/client.js:237`).
- Reproduced: `GeneratorOptions(prompt='x', checkpoint=None, unet='flux1-dev.safetensors')`
  → `ValidationError: checkpoint Input should be a valid string`.

The failure happens **before the job is created**: the preflight
(`POST /api/jobs/validate`) runs the same builder, so the user gets a generic
"Error: Request failed" and **zero jobs** — never the Missing-Models dialog
that would have told them what was wrong. Introduced by `0f835625` (the
"one request builder" commit) and never mirrored on the backend.

**1.2 · `backend_v2/core/workflow_builder.py:368` — the UNET branch is entered
only when `unet` **and** `clip` are both set.** A UNET without a CLIP
silently produces `CheckpointLoaderSimple{ckpt_name: null}`; a UNET with one
CLIP produces `CLIPLoader{type: "stable_diffusion"}` for a Flux UNET. Masked
by 1.1 today; fixing 1.1 alone exposes it.

## 6. Candidates that did **not** survive verification

Recorded so they are not re-reported.

- **Two workers claiming one job** — impossible: the claim is one statement with `FOR UPDATE SKIP LOCKED` under a per-pool advisory lock, and the UPDATE re-checks the concurrency bound in the same statement.
- **Lease expiry causing double-pay** — there is no lease at all, so none can expire.
- **Job metadata replaced wholesale on a terminal transition** — not reproducible; all four terminal writers build `metadata = dict(job.metadata_)` and merge the diagnostics key back in.
- **A double-nested event payload** — not real; `emit_job_event` wraps once and `update_job` passes a flat payload.
- **A cancel that never reaches the provider** — fixed in the 10-10 pass (one abort registry on the base class).
- **The LLM path publishing events without `task_type`** — fixed (goes through `update_job`, with `phase` for the sub-state).
- **Recovery re-paying a completed generation** — fixed (finalisation is awaited; the sweep excludes POST_PROCESSING).
- **The 300-second stale threshold failing 3600-second jobs** — fixed (per-task-type timeout; the route reports instead of failing).
- **The batch page being a second request builder** — fixed for the batch page itself; the **gallery Remix** is the remaining second builder (3.31).
- **The enhancer panel hardcoding the provider's node vocabulary** — fixed (capabilities are derived from the provider's own `object_info`).
- **Every image model reading "Partial — 2 of 4 online providers ready"** — fixed.
- **The scene's hires upscaler asking for a model named "latent"** — fixed.
- **The embedding stack having no CI coverage** — still true, still open (not re-listed; it is a dependency gap, not a code defect).
- **The 2026-10-01 "published export leaked the unfiltered owner export"** — fixed.
- **The frontend publishing the whole API on `0.0.0.0`** — the bind is now loopback + the operator's NetBird address, and the docs' claim that there is *no* host port is the defect (5.1).
- **"the app has no authentication"** — deliberate and documented; unchanged, and not a code defect to fix here.
- **Never-imported frontend files / backend modules** — measured at **0** each. The tree is clean of that class.
- **`scripts/migrate_sqlite_to_pg.py` duplicating the backend's** — it is a documented 23-line shim.
- **`remote_agent/provider_core/` duplicating `deployables/provider_worker_core/`** — two intentional forks, guarded by `tests/test_provider_core_parity.py`.
- **The `download.*` event family** — removed on 2026-10-03; the CivitAI token in the URL query string is that API's own contract, never persisted, never logged.
- **Engine contract drift (a missing method on a subclass)** — every one of the 14 engine classes implements the full base contract; the reconciler's `except TypeError` fallbacks are safe.
