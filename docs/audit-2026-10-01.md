## Disclosure: data lost during this audit

The backend sub-agent's in-process route probe called `DELETE /api/jobs` — an
unauthenticated destructive endpoint it was auditing — which **deleted all 154
rows of the `jobs` table**. Job *history* is gone.

Verified intact afterwards: 16,677 `assets` rows, 16,342 PNGs on disk, the
gallery and statistics paths. `assets.job_id` is an un-FK'd soft reference and
nothing joins on it, so no generated image was orphaned. The same agent also
rewrote `config.json` in-process and restored it with `git checkout`.

This is exactly the risk `docs/STATUS.md` item 1 records: the app has no
authentication and port 8002 is published on `0.0.0.0`. **Any agent, probe or
script pointed at this stack can destroy the database.** That is now the
highest-priority open item, and it is no longer theoretical.

## P0 — fixed here

### 1. "Copy Asset" moved the original file, and toasted "Asset copied"

`FeedCard.jsx` posted `{ copy: true }` to `POST /api/v2/assets/{id}/move`.
`MoveAssetRequest` declares **`copy_file`**, so pydantic dropped `copy` in
silence, `copy_file` stayed `False`, and control reached the `os.rename` branch
at `files.py:1148`. The "copy" **moved** the original off disk while the UI
reported success.

Silent data loss behind a success message, from a field name pydantic discards by
design — the exact mechanism the 2026-09-29b audit recorded as a repeated
"fix landed at 2 of 3 sites" failure.

Fixed both sides: the frontend sends `copy_file`, and the backend accepts `copy`
as an alias so a **stale cached bundle** cannot reproduce the destruction.
`FeedCard.copyPayload.test.jsx` drives the real handler; reverting the fix fails
2 of its 3 tests with `expected undefined to be true`.

### 2. Every 404 on three asset routes was an unmapped 500

`NotFoundError(resource, identifier)` takes two required arguments. Six sites in
`api/routes/files.py` raised it with one, so the constructor raised `TypeError`
inside the handler and FastAPI had no mapping for it.

```
before:  GET /api/v2/assets/<missing>/file  -> 500
         GET /api/v2/assets/<missing>/thumb -> 500
         POST /api/v2/assets/<missing>/move  -> 500
after:   all three -> 404
```

An AST sweep of every `ComfyError` subclass across `backend_v2` and
`provider_containers` confirms these were the **only** 6 genuine arity
mismatches. The scan is kept at `/tmp/kilo/backend-audit/arity.py`.

### 3. `GET /api/v2/models/check-installed/{id}` 500'd on any non-numeric id

The path param was declared `str` and compared against an **integer** column, so
Postgres answered `InvalidTextRepresentation`. Now declared `int`, so pydantic
rejects it at the boundary: non-numeric → 422, numeric → 200 unchanged.

Note the trap this exposed: the suite runs on SQLite, which returns no rows
instead of raising, so a "not 500" assertion **passed against the broken code**.
The test now asserts 422 specifically, which fails on both engines.

### 4. `PUT /api/v2/world-vault/graph-layout` accepted an unbounded body

Measured by the backend agent: 50,000 nodes → **16,662 ms** in one request, and
while that write ran, `GET /api/health` went from 3 ms to 20 ms median / 218 ms
p95 / 1,385 ms max. Unauthenticated, no cap.

Four defects in one route, all fixed: no request schema (it published an empty
object schema), no cap, an ad-hoc `HTTPException` instead of the domain
`ValidationError`, and `float(x)` on arbitrary input — a **fourth** unmapped
500 on `{"x": "nope"}`, now a 422.

`after: oversize -> 400, bad x -> 422, normal -> 200`

### 5. `GET /api/statistics/summary` — uncached, 1.5–3.1 s, no callers

The only one of three statistics routes without `@cache_stats`, and it runs the
**full** base aggregate (7 GROUP BYs + a 16k-row jsonb pass) to return six
numbers. 20 concurrent requests took 38.6 s. Zero frontend callers.

### 6. `Activity` rendered a failed fetch as "No events yet"

`pages/Activity.jsx` had no `isError` branch at all, so a backend error told the
user their world was empty. Same class as the `Worlds.jsx` P0 from 2026-09-29b,
in the next page over.

### 7. Global shortcuts fired through open dialogs

`useKeyboardShortcuts` guarded modifier keys and "is the user typing", but not
"is a dialog open". So `g` navigated away from under an open modal and discarded
its state, and on the Dashboard `Delete`/`Backspace` reached `handleDelete` with
a confirmation dialog already up — the exact action the pointer path asks the
user to confirm.

Fixed by exposing the registry `useEscapeKey` already maintains
(`hasOpenEscapeDialog()`), so the answer is *asked* rather than inferred from
the DOM — a dialog can close itself on a button without ever registering an
Escape handler.

### 8. 19 routes ran synchronous SQLModel on the event loop

Instrumenting `Session.exec` and recording the calling thread (a runtime
observation, not a reading): **19 of 152** `async def` routes did their DB work
inline on the loop. `GET /api/jobs` went from 29.5 ms at concurrency 1 to
440 ms at 16 — fully serialised. `/providers/status-cards` issued 38 loop-thread
queries.

The cause is uniform and structural: `async def` route → `async def` service with
**no `await`** over synchronous `session.exec`. `async def` is decorative — it
gets none of the loop's concurrency and gives up the worker thread.

**Fixed the 11 provably-safe ones** by converting them to plain `def`, which
FastAPI runs in a worker thread. These were verified to contain no `await` at
all, so the conversion is semantics-preserving. This matches the idiom
`/api/ready` already documents in place.

**The other 12 were deliberately not converted.** They `await` an `async def`
service that itself never awaits, and one of them (`create_job`) must
`await queue_manager.enqueue`, which is **loop-affine**. A blanket fix would
have moved paid job submission onto a private event loop in a worker thread. I
attempted that change, identified the loop-affinity hazard, and reverted it —
recorded here rather than quietly dropped.

Instead the **invariant** is now pinned: `tests/test_event_loop_invariant.py`
asserts the rule over the whole route tree, with a self-check that the sweep
found >200 handlers (so it cannot pass vacuously if the routes move), an
allowlist where each entry must still be a real route that still awaits, and a
test that every converted handler stays converted. Reverting one conversion
fails 2 tests.

This closes the gap the backend agent identified: the existing
`test_event_loop_blocking.py` asserts *named* handlers, so all 19 passed.

### 11. ⚠️ CORRECTION — the first pass of this audit reported a false negative

**An earlier version of this document claimed "there is no horizontal overflow
on any route at any width". That was wrong, and the method was the reason.**

`components/Layout.jsx:218` puts `overflow-x-hidden` on the app root. So
`document.documentElement.scrollWidth > window.innerWidth` is **structurally
incapable of reporting overflow** — it is always false, on every route, at every
width. The measurement was reading an element that by construction cannot
disagree.

The correct metric is the scroll container's own
`scrollWidth − clientWidth`, and whether the excess is *reachable*: content in an
`overflow-x: auto|scroll` ancestor is fine, content in an `overflow-x: hidden`
one is not, because nothing can scroll to it. Re-measured that way, the first
pass had missed:

| Route | Clipped | Unreachable controls |
|---|---|---|
| `/gallery` | **1,836 px** | **32** (43 of 48 date-rail bars) |
| `/story` @768 | 220 px | 6 (Narrate, Export, Publish, Add, the beat input) |
| `/providers` @768 | 146 px | name rendered at **0 px wide** |
| `/prompts` @360 | 48 px | 1 ("New Prompt") |
| `/statistics` @768 | 115 px | 2 ("30D", "ALL TIME") |
| `/settings` @768 | 11 px | 1 (a `<select>`) |

All fixed. **Final measured state at 360, 390 and 768 px: 0 unreachable
controls on all 24 routes.**

The four P0 root causes:

1. **The 44px tap-target floor overflowed a dense chart.** `GalleryDateRail`
   packs up to 48 columns into a ~320px rail, each `flex-1 min-w-0`. A min-width
   of 0 cannot beat `min-width: 44px`, so every bar floored at 44px —
   48 × 44 = **2,112 px** inside a 360px rail. **43 of 48 date bars were
   permanently unclickable**, and the root's `overflow-x-hidden` made it
   unrecoverable. The `no-touch-padding` opt-out is the documented escape hatch
   and these bars did not carry it. Fixed by giving the bars `no-touch-padding`,
   an 8px `chart-mark` floor, and `overflow-x-auto` on the rail (measured
   `scrollWidth` 431 vs `clientWidth` 286, so all 48 stay reachable).
2. **Full-bleed main had `overflow: hidden` on both axes** with no horizontal
   fallback, clipping the story beats toolbar. Now `overflow-y-auto
   overflow-x-auto`.
3. **The mobile gallery FAB sat *inside* the action bar.** The bar is
   `fixed bottom-0` at z-30, 81px tall; the FAB was `bottom-6` (24px) at z-40.
   Measured over a 24×24 grid at 360×800, the FAB covered **22% of the Generate
   button's area** on `/generate` and **16%** on `/img2img` and `/inpaint` — the
   primary action, under the thumb, partly dead. Now `bottom-28`.
4. **`min-w-0` let flex collapse a column to nothing.** `ProviderListItem`'s
   name column had `min-w-0` with no floor, so a ~662px row of `flex-shrink-0`
   badges took the whole 704px card and the provider name and description
   rendered at **0px** at every width ≥640px. Now `sm:min-w-[14rem]`, with the
   action row wrapping.

Plus six flex rows that could not fit and had no `min-w-0` or `flex-wrap`:
`Prompts` (New Prompt 48px out), `Statistics` (2 tabs out), `SettingGroup`
(a `<select>` 11px out — its automatic minimum is the longest option, so
`min-w-0` alone cannot help; the two-column layout now starts at `lg` not `md`),
`SamplingSettings` seed row, `DiscoverTab` URL import (the only way to import a
model by URL was 11px outside the viewport), and `ProviderListItem`'s actions.

`frontend_v2/src/test/mobileLayoutInvariants.test.js` pins all of it as 13
CSS-level tests, including the fact that `documentElement.scrollWidth` is not a
valid signal here. 8 of the 13 fail against the pre-fix source.

## Verified fixed, previously reported — no longer defects

So the next audit does not re-hunt them:

- `ModalOverlay` **does not need** `role="dialog"`. 22 of the dialog components
  already declare it **on the panel**, which is the correct element; the overlay
  is the backdrop. Adding it there nests a dialog in a dialog — rejected by
  testing-library and resolved arbitrarily by assistive tech. I implemented this,
  broke 8 existing tests, and reverted it. **The 2026-09-29b claim that "26 of 31
  overlays have no dialog role" is wrong**; 15 consumers genuinely lack it and
  need the role on their panel.
- React Query v4 positional API: **0** remaining across 279 declarations.
- `['installed-models']`, `useTimeline` invalidation, `useAssetTags` producer,
  the 44 px `@media` block, `btn-primary`/`nav-active`: all genuinely present.
- Route reachability: **0** frontend 404s, **0** wrong-method. All 235 distinct
  frontend calls bind to a live operation (249 paths / 329 operations).
- Path traversal: `get_safe_path` is sound; all 7 probes refused.
- WebSocket: 3 emitted events have no listener (`download.progress`,
  `model.sync_progress`, `reconciliation.failed`). Missed-event recovery is
  sound — replay on reconnect plus a 20 s watchdog.

## Still open — not fixed, ordered by cost

### P1

1. **No authentication, and it has now cost real data.** See the disclosure
   above. `DELETE /api/jobs`, `DELETE /api/v2/world-vault/graph-layout` and every
   other destructive route is reachable by anything that can reach port 8002,
   which compose publishes on `0.0.0.0`. **Nothing destructive should be
   exercised against this stack until this is fixed.**
2. **12 routes still block the event loop** — the `await`-chained half. Each
   needs its service method made synchronous and the call hoisted into
   `asyncio.to_thread`. One production caller each; scoped and registered in the
   new invariant test's allowlist.
3. **WebSocket rooms are one per topic, not per entity.** `websocket.py`
   derives the room from `event.type.split(".")[0]`, and there is no `chat_id`
   filter on the streaming path in `useChatStreaming.js`. A `job.completed` for a
   suggestion in chat B, delivered to a client viewing chat A, writes chat B's
   text into chat A's composer. Single-user today, so latent; wrong the moment
   the app is shared.
4. **Client-supplied primary keys are persisted.** `create_entry`,
   `create_character`, `create_lorebook` and `create_chapter` take SQLModel
   **table** classes as request bodies. Reproduced live: posting
   `{"id": "client-chosen-id-12345", ...}` to
   `POST /api/v2/lorebooks/{id}/entries` returns that exact id. Needs explicit
   `Create` request models that exclude `id`/`created_at`/`updated_at`.
5. **Dead code, for the fourth consecutive audit**: 9 backend functions

## Root causes — the five that keep recurring

1. **A fix lands at the site the report names; equal sites keep the defect.**
   This has now happened in three consecutive audits. The 2026-09-29b audit says
   so itself. The 2026-10-01 instances: `NotFoundError` (6 sites, all named),
   `useMutation` identity (5 consumers), `metadata_` vs `metadata` (14 copies),
   and the event-loop routes. **The fix that works is making the defect
   structurally impossible, not finding every site**: the arity sweep, the
   event-loop invariant test, and `jobMetadata()` each retire a whole class
   rather than a list.
2. **A green suite proves the payload, not the property.** `statistics/summary`
   was uncached and no test noticed, because deleting `@cache_stats` changes no
   response body. `check-installed` passed against the broken code because SQLite
   does not raise where Postgres does. Assert the *property* — a 422, a thread
   id, a response time — or assert nothing.
3. **No authentication turns any mistake into data loss.** A 40-line audit probe
   deleted the job table. This is the one finding that will keep recurring no
   matter how good the code is.
4. **A primitive that supplies part of a contract makes adoption optional.** 34
   `ModalOverlay` consumers, but the role lives on the panels and 15 panels have
   none. A primitive that owns *all* of it, or none, has one adoption state.
5. **Tests are enumerated, not invariant-based.** `test_event_loop_blocking.py`
   names 6 handlers and 19 pass; three of the 2026-09-29b audit's own regression
   tests were not load-bearing on first run and had to be rewritten. Every fix in
   this pass was verified by reverting it, and two of my own tests were rewritten
   for exactly this reason before they were correct.

## What was deliberately not done

- **The blanket `deduplicated` thread-hop.** One edit there would have moved 19
  routes off the loop, including `create_job`'s `await queue_manager.enqueue`,
  which is loop-affine. Reverted after identifying the hazard.
- **The 12 remaining loop-blocking routes.** Paid-path refactor with one
  production caller each and ~20 test call sites; not something to do as a
  drive-by inside an audit pass. They are now enumerated and pinned.
- **A blanket `async def` → `def` conversion.** Only the 11 with provably no
  `await` were converted.
