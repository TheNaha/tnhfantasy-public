## 2. Fixed in this pass

Each fix has a test that was confirmed to **fail before the fix and pass after**
(revert-verified). This is the standard the previous passes set, and it is the
reason any of these survived: in every case below the existing suite was green
against the defect.

### 2.1 P0 — the entire mobile stylesheet was applying at desktop width

`frontend_v2/src/index.css` — a stray `}` closed `@media (max-width: 768px)`
eighty lines early, and the block's real closing brace was missing at the end of
the file. 55 rule groups belonging to the phone breakpoint were emitted at top
level, applying at every viewport. Confirmed in the shipped bundle, not just the
source.

Introduced by `295f8888` ("fix(mobile): four CSS rules, three of which were
unreachable as written") — the fix for one finding created this one, and it is
committed, not merely local.

Measured on the running stack at 1440px, before → after:

| | before | after |
|---|---|---|
| `input[type=range]` height | 44px | **16px** |
| `input[type=range]` touch-action | `none` | **`auto`** |
| `input[type=range]` appearance | `none` | **`auto`** |
| `.max-w-6xl` / `.max-w-7xl` max-width | `100%` | **1152px** |
| `.glass-panel` backdrop-filter | `none` | **`blur(16px)`** |

`touch-action: none` on every slider meant a desktop user could not scroll the
page by dragging on a slider. At 390px and 768px nothing changed — the mobile
rules still apply, as intended.

Why nothing caught it: all 15 pre-existing tests in
`src/test/mobileLayoutInvariants.test.js` regex `index.css` and **never check
block membership**. A rule can be in the wrong block and every one of them
passes. Four new tests parse the stylesheet with postcss and assert that nothing
the phone breakpoint declares also sits at top level. Reintroducing the stray
brace fails all four and passes all fifteen originals.

### 2.2 P0 — an unauthenticated GET soft-deleted unrelated gallery rows

`backend_v2/api/routes/files.py` — `_soft_delete_assets` matched a basename with
`Asset.relative_path.endswith(rel)` and **no path-separator boundary**, so a
request for `abc.png` matched `notabc.png` and `xabc.png` too. The exact-path
arms above it can never match, because `relative_path` is always the
date-partitioned form — so *every* basename-keyed call landed in the over-broad
branch.

Two reachable callers, neither requiring a user mistake:

- `GET /api/thumbnail/{size}/{filename}` — the "self-heal a missing index row"
  fall-through. Any thumbnail miss deleted its neighbours from the gallery.
- the gallery's batch delete, which the UI sends as bare filenames.

Reproduced before the fix: requesting `abc.png` returned `4` deletions, not `1`.
Ten regression tests, generated over the whole asset table rather than
hand-picked rows. The function previously had **no tests at all**.

### 2.3 P1 — the e2e CI job could not have been green

`frontend_v2/e2e/fixtures.js` prefixed `/api/v2` onto every path it was handed,
but `/api/settings`, `/api/prompts` and `/api/jobs` are unversioned. Fourteen
call sites across five specs requested routes that do not exist, and every helper
throws on `!res.ok()`.

The doubling is documented in `docs/api.md:244`, which described
`GET /api/v2/timeline/timeline` as real and *invented a reason for it*. One wrong
belief, two consumers — the document then the test.

Fixed in one place (`resolveApiPath`) rather than at 46 call sites, and the
unversioned routes are now named in full. `backend_v2/tests/test_e2e_endpoint_
contract.py` now walks every spec, resolves each path the way the harness does,
and asserts it exists in `app.openapi()`.

### 2.4 P0 — every artifact fetch from a remote GPU rig raised `AttributeError`

`provider_containers/image_worker/engines/remote_comfy/client.py` called
`client.stream(...)` on the object `get_http_client()` returns. That object is a
`SharedHttpClient`, whose surface is
`get/post/put/delete/get_client/close/config` — it has no `stream`. The router
flattens the failure to a 500 carrying `retryable: true`, so the backend re-ran
the same work on another provider and paid for it.

The test missed it because it replaced the *client* rather than the *pool*: it
patched `get_http_client` to return a bare `httpx.AsyncClient`, which does have
`.stream`. The fake is now the real `SharedHttpClient`, and a new structural test
asserts no engine calls a method the wrapper does not have. Both test files that
had masked it are fixed.

### 2.5 P0 — `REMOTE_AGENT_ALLOW_INSECURE` bound a write API to every interface

`remote_agent/agentctl.sh` did `export HOST="${HOST-}"`, which exports `HOST=""`
when unset. `server.py` read `os.getenv("HOST", "0.0.0.0")` — the variable *was*
set, so the default never applied — and `""` was in `_LOOPBACK_HOSTS`, so the
clamp returned it unchanged. uvicorn binds `""` as `INADDR_ANY`.

Net effect: the flag documented as "local dev, single user, loopback" exposed
`/delete-model`, `/delete-file`, `/upload-file` and `/download-model` —
read-write on the ComfyUI models mount — on `0.0.0.0:8001`.

Fixed at both ends: the server treats empty as unset, `""` is out of the loopback
set, and the launch script no longer manufactures the value. Five regression
tests, including one that reads the shell script (a Python test cannot execute
it, and the file it launches is a frozen binary).

### 2.6 P1 — TTS cancellation was dead

`tts_worker/engines/modal/client.py` overwrote the tracker its base class had
just installed with `runtime_config.get("job_tracker")` — a key
`build_runtime_config` has never produced. So `self.job_tracker` was always
`None`: `POST /cancel-job` raised `AttributeError` (a 500 marked retryable), and
`inference`'s `if job_id and self.job_tracker` guards meant nothing was ever
registered, so a cancellation could not be observed mid-stream.

The test passed because it constructed the client with
`{"provider_id": "p", "job_tracker": tracker}` — a shape nothing builds. New
tests go through `select_client(TTS_ENGINES, "modal", build_runtime_config(...))`.

### 2.7 P1 — a provider stayed "reconciling" for three hours

`trigger_reconciliation` treated any HTTP 200 as "work started" and persisted
`reconciling / starting / "Reconciliation started in worker"`. True for
`image_worker`, which reports back. False for the LLM and TTS workers, which have
no model tree, answer `ok`/`skipped` synchronously, and never push a terminal
state — so nothing ever moved the row.

Live on the running stack: `llm-local` and `tts-modal-hp196` both frozen at that
message with `updated_at` unchanged, `total_models: 0`.
`RECONCILIATION_IN_PROGRESS_TTL` is 10800s, so each manual trigger produced three
hours of a card claiming to be busy while the worker answered in milliseconds.

The worker's own vocabulary is now honoured, and an unrecognised status defaults
to *terminal* rather than busy. `setup_models`, twenty lines away in the same
file, already read `worker_status` and branched on it; this was the same decision
not repeated.

### 2.8 P1 — a TTS provider's card claimed to track 525 image models

`get_provider_sync_stats` special-cased `worker_type == "llm"`, so a TTS provider
fell through to the image branch. Live: `tts-modal-hp196` reported
`"is_image_provider": true, "catalog_models": 525, "total_models": 0`. Now keyed
on *"is it an image provider"* rather than on an enumeration of what is not, so
the next worker type added is covered by default.

### 2.9 Smaller, all reverted-verified

- **The 9 mobile Playwright tests ran in no CI workflow.**
  `frontend-e2e.yml` passed `--project=chromium`, whose config excludes
  `mobile-responsive.spec.js`. The only real measurement of tap targets,
  overflow and header wrapping was manual — which is how §2.1 shipped. A second
  step now runs `--project=mobile-chromium`.
- **`docs/api.md` is now generated and drift-checked.** It covered 131 of 249
  paths, no test referenced it in any language, and it documented a route that
  does not exist. `scripts/generate_api_docs.py` writes the index from
  `app.openapi()`; `tests/test_api_docs_contract.py` checks both directions. The
  convention is now explicit: a path being *denied* goes in a fenced block, so
  the three real corrections stopped reading as ghosts.
- **`preflight.sh` now reports the one thing that makes a whole feature dead.**
  It said "1 of 6 providers are switched off" and left the operator to work out
  which. It now fails loudly when no LLM provider is enabled, which is the live
  state of this instance (§3.1).
- **`provider_containers/bench/` was missing from CI's `compileall`.** Same
  omission that was once fixed for `tts_worker`; a syntax error there shipped
  green.
- **`StorySandbox.test.jsx` had a `waitFor` timeout that overrode the suite's own
  load headroom.** `vite.config.js` sets `asyncUtilTimeout: 5000` with a comment
  describing exactly this failure, but this one test passed an explicit
  `{ timeout: 3000 }`, silently reinstating the default window. It needs ~2.7 s
  in isolation, so it had under 300 ms of headroom. Now 10 s.

### 2.10 Test-suite flakiness, measured rather than guessed at

Two separate mechanisms, and conflating them is how this gets misdiagnosed:

- **Known and already mitigated.** Running the backend and frontend suites
  *concurrently* produces a spread of unrelated `waitFor` timeouts across the
  frontend. `vite.config.js` already documents this and sets
  `asyncUtilTimeout: 5000` with `maxWorkers: 4`. Confirmed during this pass: with
  both suites running, the frontend failed one test per run and a different one
  each time; run alone, 1468/1468. **Do not run the two suites in parallel on one
  host** and do not read a single failure under that condition as a regression.
- **Real gap, fixed.** A test that passes an *explicit* timeout smaller than the
  configured headroom silently overrides it — `StorySandbox.test.jsx` did, and
  was the one failure that persisted under load.

The backend's equivalent is still open: `test_lifespan_runs_every_declared_
startup_phase` starts real threads and polls the event loop, and remains the
suite's known flake. Its runtime is 14–18 minutes of the backend suite's total,
so splitting the slow boot tests into their own CI job would shorten the signal
loop as well as stabilise it.

## 6. Refuted during this pass — do not re-raise

- "Frontend calls routes that do not exist." Zero, across 254 call sites. The
  14 that 404 are all in the **e2e harness** (§2.3), not the app.
- "Two whole sections are mounted under the wrong URL prefix." Not present. Both
  sides agree on `/api/v2/*` versus unversioned `/api/*`.
- "`docs/api.md` documents 12 bogus paths." 6 are headings and path-parameter
  examples. 3 were genuine, and one of those was a *correction* in prose that the
  scanner misread until the convention was made explicit.
- "The validation magic-byte table is still unpacked backwards." Fixed. Only one
  real table remains and it maps bytes → format name correctly.
- "`VALID_FILE_HEADERS` has siblings with the same shape." It does not.
- "The event-loop invariant register is stale." It is not — no stale entries, and
  the resolver test holds. It is *incomplete*, which is a different finding.
- "The §3.11 re-park path is unreachable." It is reachable, and tested.
- "Migrations are not individually transactional." Each runs in its own
  `conn.begin()`, and `_migration_080` uses per-index savepoints.
- "There is SQL injection / SSRF / path traversal." None reachable. Every user
  value is bind-parameterised; `get_safe_path` rejects every escape constructed
  against it; `parse_model_url` extracts IDs and rebuilds canonical URLs.

## 7. One incident, recorded

While proving the §2.1 guard could fail, I ran `git checkout --
frontend_v2/src/index.css` to restore a known state. That discarded four
uncommitted lines from the in-progress consolidation pass, which turned out to be
a partial fix for the `group-hover/card` touch rescue. The
`hoverRevealInvariants` guard caught the regression on the next run; the entry is
restored and both directions are now tested. No other file was touched, and the
lesson is the one this repository keeps relearning: **a guard that cannot see the
code is not a guard** — including a human reverting a file.
