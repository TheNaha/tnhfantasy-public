## The five findings that mattered

### F1 — The LLM Modal provider deleted every model on its volume, every two hours

`llm_worker/engines/modal/modal_app.py:388-391` (pre-fix)

`VALID_FILE_HEADERS` maps magic **bytes** to a format **name**
(`{b"PK": "zip/ckpt", b"GGUF": "gguf", …}`). The validator unpacked it backwards:

```python
for header_sig, expected in VALID_HEADERS.items():
    if header[:len(expected)] == expected:   # bytes slice == str -> always False
```

`bytes != str` in Python 3, so the branch never matched. Every file over
`MIN_MODEL_SIZE` fell through to `{"status": "invalid", "reason": "Unknown file
format"}`, and `validate_directory` then `os.remove`d it. `run_reconciliation_v2`
hardcodes `validate_existing(True)` → `validate_models(["models"], True)`, so step
0 of the two-hourly loop wiped the volume. The log line read
`"✓ Cleaned up N invalid + 0 partial files"`.

`provider_core/validation.py` owns this rule, and the image Modal app already
called it. Only the LLM twin re-implemented it. The manual "Validate all" button
passes `False`, so it was safe and hid the bug.

**Fixed.** Replaced the third copy with the shared `validate_downloaded_file`,
which is also the de-duplication. `tests/test_llm_modal_validate.py` (9 tests)
drives the real deployed function and covers the control cases too: a corrupt
`.safetensors` is still swept, and an in-flight temp is still reported as
`partial` and never unlinked.

### F2 — Chapter autosave destroyed the beat list, silently, every few seconds

`api/routes/world_vault/stories.py:770` (pre-fix)

`update_chapter` took `chapter_update: StoryChapter` — a SQLModel **table**
model. FastAPI skips pydantic validation for a table class, so a PUT of
`{"content": "..."}` (exactly what `useUpdateChapter` sends) left `beats` at its
column default of `[]`, and `if chapter_update.beats is not None` read that as an
explicit instruction to clear them.

The editor autosaves 2 s after every keystroke batch. Verified:
`StoryChapter(content='x').beats == []` and `[] is not None` is `True`.

**Fixed.** New `ChapterUpdate(BaseModel)` with every field optional, so absent
means "leave alone". The revision snapshot also moved from an inline
`session.add` to `StoryChapterRevisionRepository.create_snapshot`, which is the
only implementation that enforces `MAX_REVISIONS_PER_CHAPTER` — the autosave path
was accumulating hundreds of uncapped full-text snapshots per chapter.

### F3 — The job-completion event dropped the job's metadata, silently

`services/job_service.py:656` (pre-fix)

```python
await emit_job_event(event_type, {**(self._job_to_dict(job)), **(event_extra or {})})
```

A **shallow** merge. Six completion paths build `event_extra["metadata"]` from
two or three keys of their own (`chat_id`, `type`, `regenerated`), so the job's
real metadata was replaced rather than extended. `world_integration_service` reads
it from the far side. Measured: 5 keys in, 2 keys out.

Consequences, all on the job-completion path:

- `character_id` never reached `Message` → every AI reply in a **group chat** was
  attributed to the primary character
- `is_swipe` / `target_message_id` never arrived → the alternate branch was
  unreachable, so "generate an alternate reply" **appended a new message** while
  the UI reported success
- `orchestrator_depth` was never stamped
- `is_suggestion` was lost

Invisible to the tests: `test_generate_swipe.py` only covers the route, and
`test_world_integration_service.py` hand-builds a complete metadata dict,
bypassing the merge that drops it.

**Fixed** in one place (`_build_event_payload`) so all six sites are covered.
`event_extra` still wins per key, so a caller can correct a value.

### F4 — The group-chat roster could never be written

`api/routes/world_vault/chats.py:107-153` (pre-fix)

`additional_character_ids` was missing from both `UpdateChatRequest` and
`CreateChatRequest`, and pydantic's default `extra='ignore'` dropped it without a
word. `ChatContextPanel` PATCHed it and the mutation applied an optimistic cache
update, so the add/remove buttons appeared to work right up until the next
refetch, then the roster vanished. Everything downstream — the message list, the
prompt context builder, the idle simulator, the SillyTavern `group_characters`
export, the reference scrubber — read the permanently-`[]` column.

**Fixed**, with existence validation on each id and a rejection of the primary
character as a roster member (a dangling id silently drops a speaker from the
prompt, which surfaces as "the character I added just never replies").

### F5 — The gallery virtualizer measured the wrong box, on every desktop visit

`components/dashboard/GroupedDashboardContent.jsx:419` (pre-fix)

`useWindowVirtualizer` bound to `window`, but `Layout.jsx:370` sets
`lg:overflow-hidden` on the page wrapper and gives the scroll to an inner
`lg:overflow-y-auto` pane. `window` never scrolls, so the virtualizer's scroll
listener never fired, its offset stayed 0, and it rendered only the first
viewportful and never advanced.

This is the **dangerous direction** for a test: bound to `window` it always had a
height, so it always rendered *something* — which is why it survived review and a
green suite while being broken. Two siblings had the same root cause
(`TimelineView`, and `useVirtualListScrollMargin` adding `window.scrollY` — always
0 — to a viewport-relative `rect.top`).

Measured on the running stack before the fix: `/api/v2/gallery?limit=48` 284 ms,
`/api/v2/assets/dates` 304 ms, `/api/v2/assets/facet` 89 ms — the gallery's
critical path was ~677 ms of backend time, all on a 16.5k-asset library.

**Fixed** with one shared resolver (`hooks/useScrollRoot.js`) used by the
observer, the gesture listeners, and both virtualizers. Two subtleties the naive
fix gets wrong, both now covered by tests:

- `useVirtualizer` pointed at `window` renders **nothing** — the library's
  `getRect` reads `offsetHeight`, which is `undefined` on `window`, so the
  visible range is `NaN`. `observeElementRect` is overridden to use
  `innerWidth/innerHeight`, which is the only reason `useWindowVirtualizer`
  exists.
- A resolved element with `clientHeight === 0` cannot display anything, so it
  falls back to the viewport rather than rendering an empty box.

## Measured: the backend event loop is fully serialized

This is the largest single performance defect, and it is architectural.

| Measurement | Result |
|---|---|
| Single `GET /api/settings` | 9.2 ms |
| 20 concurrent `GET /api/settings` | **400 ms wall** (20 ms each) |
| 20 concurrent `GET /api/v2/gallery?limit=48` | 3098 ms wall (284 ms solo) |

Effective concurrency is **1×**. 196 `async def` handlers in `api/routes/` run
synchronous SQLModel stacks on the event loop. An AST sweep found 0 *sync-only*
handlers suitable for a mechanical `async def` → `def` conversion, because the
blocking work is inside the repositories and services the handlers call — so
there is no cheap global rewrite here. The 2026-09-27 note that this class was
fixed is only true for a handful of specific call sites.

Highest-frequency offenders, fixed in this pass:

- `services/provider_client.py` — the image reducer wrote the `jobs` row on every
  `node` and `progress` event. A 20-step SDXL job produced 40-60
  `update_job` calls, each a synchronous SELECT + UPDATE + COMMIT + REFRESH plus
  a websocket broadcast and a flushed log line, and every gallery / job-list /
  provider-status request queued behind them. Progress rows are now coalesced to
  1 Hz; the websocket event is untouched, so the UI still updates smoothly. No
  flush is needed and none is written: every terminal branch discards the pending
  frame, and a stream that ends with no terminal event raises in `finalize()`.
- `services/orchestrator_service.py:846` — a synchronous sentence-transformers
  forward pass in an `async def` agent tool. Moved to `asyncio.to_thread`, the
  same fix already applied at `job_processing.py:490` for memory extraction and
  missed here.
- `services/rag_pipeline.py` — `search_memories` ran the embedding pass inline.
  Split into `search_memories_async`, which offloads the model forward (the
  expensive part) and leaves the bounded indexed query alone. Added
  `q_vec`/`q_vec_computed` so the sync path and the async path cannot disagree.
- `api/routes/providers/crud.py:241` — two uncached, timeout-less Docker socket
  reads in an `async def`. `container_manager`'s own docstring says to call it
  from `asyncio.to_thread`; the sync path was never converted.

Still open and worth scheduling: the per-image commit rollup in
`world_integration_service._handle_chat_image` (3N queries, N commits for a
64-image batch), `JobService.update_job`/`get_job` themselves, the
`agent_simulation` idle tick, and the `characters.py`/`locations.py` sync file
writes of up to 5 MB.

## CI was silently validating nothing

`.github/workflows/provider-tests.yml:80-86` ran
`docker compose … config --quiet` as the **first** step of the `build` job. Every
`.env*` file is gitignored, so on a clean checkout compose refuses to render:

```
$ git archive HEAD | tar -x -C /tmp/clean && cd /tmp/clean
$ docker compose -f docker-compose.yml -f docker-compose.dev.yml --profile providers config --quiet
env file /tmp/clean/.env.modal-hp196 not found
EXIT=1
```

The job was therefore red at step one, and the three `docker build`s below it
**never ran**. `docs/STATUS.md:54-57` claimed CI now builds all three provider
images and validates the compose file; it did neither, and could not.

Fixed by seeding the required env files from the examples that mirror them.
Verified: the same command on a clean tree now exits 0.

Also confirmed and worth acting on separately: `backend_v2/Dockerfile` and
`frontend_v2/Dockerfile` are built by no workflow at all, and the base
(production) compose file is never rendered by CI — only base+dev with
`--profile providers`.

## Ordering rationale

The order was: anything that destroys user data, then anything that makes a
documented feature do nothing, then correctness of what the UI displays, then
performance, then consolidation, then docs.

F1 and F2 were first because they are unrecoverable — a wiped model volume and a
destroyed beat list. F3 and F4 were next because they are the root cause of three
separate "the feature is inert" reports (group attribution, swipes, the group
roster), and both were one-place fixes that covered six and two call sites
respectively. F5 and the event-loop measurement came before the smaller frontend
items because they are the difference between a page working and not working for
every user, and because the measurement is what showed the 2026-09-27 "fixed"
claim was only partly true — worth knowing before spending more time in that
area.

The CI finding was placed above the smaller infra items for the same reason: it
had been silently reporting a green build job that did nothing, so every
provider Docker image was unvalidated.

  bounds tracebacks to 40 frames / 16 000 chars instead of handing `exc_info` to
  `ConsoleRenderer` → `RichTracebackFormatter`, which walked frame locals.
- **`get_config()` does not re-read `config.json` per request** — `load_config`
  caches into the module global. The contrast with `update_settings`, which does
  use `to_thread`, is cosmetic.
- **`max_concurrent` is enforced exactly on Postgres** — `job_queue.py` counts
  claimed-but-still-PENDING rows under `pg_advisory_xact_lock`, so the ceiling is
  not `max_concurrent + max_workers`.
- **Postgres restart recovery is complete** — `QueueManager.recover` resets every
  active status and clears claims; the in-memory `max_workers=1` default is
  overridden by `configure_worker_pool` at startup.
- **Provider auth is sound.** `PROVIDER_WORKER_TOKEN` fails closed with 503 on
  both `/inference` and `/deploy`, uses `hmac.compare_digest` after a
  `not provided` short-circuit, and all six provider services pass the token via
  `environment:` (the only mechanism that interpolates from the host `.env`).
- **Partial downloads are never deleted by an unclassifiable pass.** The image
  Modal app classifies transient artifacts and does not delete them; Beam and the
  LLM app bucket undersized files as `partial` with no delete, and both have an
  `is_transient_artifact` guard that short-circuits first. `utils.py:20-41`
  documents the original incident accurately and the code matches.
- **`_LLMReducer`'s 60 fps emit is throttled** by `time.perf_counter()`, so it is
  not an unbounded event storm.
- **The base+dev port merge is correct** — the rendered config has exactly one
  `8002` and one `5174` mapping plus `5432` only in dev. No collision.
- **Every `condition: service_healthy` target has a healthcheck**, and every
  healthcheck is satisfiable (`wget` is installed in both frontend targets).
- **`worker_ws`'s `_worker_owns_job` gate holds** — a minted token cannot fail a
  job assigned to a different provider.
- **`list_jobs`' `next_cursor` mutation is safe** — it happens after
  `deduplicated` returns, so the 3 s result cache is not polluted.
- **No string-concatenated SQL** in the core routes, and **no named volume
  shadows a bind mount** anywhere.
