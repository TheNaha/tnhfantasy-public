## Findings

### 1. Critical & High-Severity Bugs

#### [BUG-01] `async def` passed to `asyncio.to_thread` + detached ORM access in comic export
- **Severity:** High
- **Location:** `backend_v2/api/routes/world_vault/stories.py:2945-3005`
- **Evidence:** `JobService.update_job` is `async def` (`services/job_service.py:847`), yet `_run_export()` calls `await asyncio.to_thread(task_job_service.update_job, job.id, ...)` at `:2945` and `:2984`, discarding an unawaited coroutine and leaving the job `PENDING` forever. It also reads `job.metadata_`, `chapter.chapter_number`, and `task_job_service._job_to_dict(job)` from ORM rows loaded on the closed request `session`.
- **Fix:** Snapshot `job_id`, `initial_metadata`, and `chapter_number` before spawning `_run_export`; call `updated = await task_job_service.update_job(...)` directly and serialize `updated` for `emit_job_event`.

#### [BUG-02] Broken `to_thread` on `async def` + listener crash & shutdown leak in `worker_registry.py`
- **Severity:** High
- **Location:** `backend_v2/infrastructure/worker_registry.py:526, 575-591, 786, 858-942`
- **Evidence:**
  1. `_provider_has_ws_connection` (`:575`) is `async def` containing synchronous `psycopg2.connect`, called via `await asyncio.to_thread(_provider_has_ws_connection, provider_id)` (`:526`) — returns an unawaited coroutine (always truthy!), bypassing the cross-process liveness check. Also `:585` places `%s` inside SQL quotes (`INTERVAL '%s seconds'`).
  2. In `_run_notify_listener` (`:858-942`), `result = future.result()` (`:892`) only catches `TimeoutError`. When a worker disconnects or fails (`ProviderCallError` set on the future), `future.result()` throws and crashes the entire `worker_dispatch` listener thread for the process without `forget_job_future`, `_release_worker_slot`, or `_write_result_async`. Line `:858` also calls `loop.create_future()` from the worker thread, and `:786` (`while True:`) has no shutdown flag.
- **Fix:** Make `_provider_has_ws_connection` synchronous `def` with valid parameterized interval SQL; catch `Exception` around `future.result()` to clean up and write failed outbox result; create `Future` on the event loop; add shutdown `threading.Event` signaled on cancellation.

#### [BUG-03] `POST /api/v2/models/maintenance/resync-all` calls `start_background_task` from sync thread + missing rollback
- **Severity:** High
- **Location:** `backend_v2/api/routes/models/maintenance.py:644-654, 677-712`
- **Evidence:** `resync_all` (`:677`) is a plain `def` route running in FastAPI's AnyIO threadpool with no running event loop; `:706` calls `start_background_task(...)` which invokes `asyncio.create_task` (`RuntimeError: no running event loop`). Inside `run_background_resync` (`:648-653`), an exception from `bg_session.commit()` is caught without `bg_session.rollback()`, poisoning `bg_session` (`PendingRollbackError`) for remaining models.
- **Fix:** Make `resync_all` `async def`, offload `repo.get_models_for_resync` via `asyncio.to_thread`, and add `bg_session.rollback()` on failure in `_apply_one()`.

#### [BUG-04] Dead TaskEvent dialect in `world_onboarding_service.py` breaks onboarding/vision/world-tick LLM calls
- **Severity:** High
- **Location:** `backend_v2/services/world_onboarding_service.py:97-220`
- **Evidence:** `_run_llm_json` (`:138-150`) and `_run_llm_text` (`:200-212`) only inspect `event.get("event") == "token"` and `event.get("status") == "success"`. All engines emit canonical TaskEvents (`delta` with `text` and `completed` with `outputs`). `full_text` stays `""`, forcing silent `"heuristic"` fallback everywhere.
- **Fix:** Unify `_run_llm_json` and `_run_llm_text` over a shared `_run_llm_completion(...)` helper parsing canonical `delta`/`completed` events (and `error`/`failed` events for clear logging) via `engine.run_inference(...)`.

#### [BUG-05] `HybridRemoteEngine.cancel_job()` never cancels child engine jobs
- **Severity:** High
- **Location:** `backend_v2/services/engines/hybrid_engine.py:313-403`
- **Evidence:** `HybridRemoteEngine.inference` calls `self.image_engine.inference(...)` / `self.llm_engine.inference(...)` directly without registering `job_id` in the child engine's `_active_jobs`. `InProcessEngine.cancel_job` checks `if not self.is_job_active(job_id): return False` (`base.py:733-734`), so child cancellation is always a no-op.
- **Fix:** Track active child jobs (or route child execution through `run_inference` / active-job registration) so `cancel_job(job_id)` cancels and aborts in-flight child inference properly.

#### [BUG-06] Thread-unsafe shared SQLAlchemy `Session` in `in_process_reconciliation.py`
- **Severity:** High
- **Location:** `backend_v2/services/in_process_reconciliation.py:254-258, 684-841`

- **Fix:** Open and close a short-lived `get_session_sync()` per thread DB operation (matching `_run_targeted_downloads` in the same module).

#### [BUG-07] `GoogleLLMEngine` cache leak + `_ENGINE_CACHE_LOCK` & config resolution drift in `engine_factory.py`
