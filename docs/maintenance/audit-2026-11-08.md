## 3. Detailed Findings

### Critical Bugs

#### [CRIT-01] Thread-Unsafe SQLAlchemy Session Sharing in Async Upload Routes
- **Severity**: High (Blocker candidate) — Risk of database connection corruption, dropped queries, or silent rollback under concurrent uploads.
- **Location**:
  - `backend_v2/api/routes/world_vault/agents.py:306-322`
  - `backend_v2/api/routes/world_vault/characters.py:1095-1138`
  - `backend_v2/api/routes/world_vault/locations.py:175-220`
- **Evidence**:
  In `upload_agent_avatar`, `upload_avatar`, and `upload_location_image`, the request-scoped SQLAlchemy `session: Session = Depends(get_session)` was passed into `asyncio.to_thread` worker functions (`_save`, `_save_character_avatar`, `_save_location_image`). Worker threads called `session.add(...)`, `session.commit()`, and `session.refresh(...)` on the request session while the FastAPI event loop was still managing the request's connection context. SQLAlchemy `Session` instances are explicitly not thread-safe.
- **Proposed Fix**:
  Use `with get_session_sync() as db_session:` within thread-pool workers to guarantee thread-isolated database sessions, avoiding sharing or mutating the request's session across threads.

#### [CRIT-02] In-Process Reconciliation Marks Failed Remote Agent Downloads as Ready
- **Severity**: High — Failed remote model downloads (e.g. 404, 403, or upstream timeout) are marked as `ready` in the database and treated as completed downloads.
- **Location**:
  - `backend_v2/services/in_process_reconciliation.py:707-708, 1102-1105`
  - `backend_v2/services/engines/remote_agent_files.py:448-453`
- **Evidence**:
  `RemoteAgentFileMixin.download_file` intercepts failed HTTP transfers and normalizes the response to `{"status": "failed", "error": ...}`. However, `in_process_reconciliation.py` only catches uncaught exceptions around `await engine.download_file(...)` and never inspects the returned dictionary. As a result, when a download fails and returns `{"status": "failed", ...}`, reconciliation increments `stats["downloads_completed"] += 1` and calls `_write_provider_status(..., "ready", error=None)`.
- **Proposed Fix**:
  Inspect the return value of `await engine.download_file(...)` in `in_process_reconciliation.py`. If `isinstance(res, dict) and res.get("status") == "failed"`, raise `RuntimeError(res.get("error") or "Download failed")` so it routes to the failure handler.

#### [CRIT-03] Plaintext Secret Token Leak in `/api/v2/llm/catalog`
- **Severity**: High (Security) — Exposes decrypted environment and provider HuggingFace and Civitai API tokens via an unauthenticated endpoint.
- **Location**:
  - `backend_v2/api/routes/world_vault/llm_config.py:65-85, 109`
- **Evidence**:
  `GET /api/v2/llm/catalog` retrieves `HF_TOKEN` and `CIVITAI_TOKEN` from environment variables and iterates over decrypted provider credentials in `ProviderRepository.get_all()`, returning `"tokens": tokens` in plaintext in the response JSON. The identical vulnerability was previously removed from `/api/v2/models/catalog` in `test_audit_2026_10_21_model_catalog_secrets.py`, but remained present in `llm_config.py`.
- **Proposed Fix**:
  Remove the `tokens` dictionary from `llm_config.py:get_model_catalog` response, aligning with the secure pattern in `models/crud.py`.

#### [CRIT-04] `RemoteAgentFileMixin.validate_models` Diverges from Engine Interface & Hardcodes `delete_invalid=False`
- **Severity**: Medium — Breaks contract consistency across engines and prevents automated cleanup of corrupt models in remote agent providers.
- **Location**:
  - `backend_v2/services/engines/remote_agent_files.py:455, 474`
  - `backend_v2/services/engines/base.py:746`
- **Evidence**:
  All other engines (`beam_engine`, `direct_comfy_engine`, `hybrid_engine`, `llm_engine`, `modal_engine`, `worker_transport_engines`) accept `(directories: List[str], delete_invalid: bool = False)`. `remote_agent_files.py` accepted only `directories` and hardcoded `"delete_invalid": False` in the payload sent to `/validate-models`.
- **Proposed Fix**:
  Add `delete_invalid: bool = False` to `BaseEngine.validate_models` and `RemoteAgentFileMixin.validate_models`, forwarding the argument in the JSON payload.

### Integration Gaps

#### [GAP-01] `ProviderCostDashboard.jsx` Renders Empty State on Query Failure
- **Severity**: Medium — Network or server errors display as "No cost data yet" instead of an error state with retry.
- **Location**:
  - `frontend_v2/src/pages/ProviderCostDashboard.jsx:26-30, 68-75`
- **Evidence**:
  `ProviderCostDashboard` destructured only `data` and `isLoading` from `useQuery`. On error, `jobs` fell back to `[]`, which computed `byProvider.length === 0` and rendered `<EmptyState title="No cost data yet" />`, violating the query error invariant.
- **Proposed Fix**:
  Destructure `isError, error, refetch` and render `<QueryErrorState noun="provider cost data" error={error} onRetry={refetch} />` when `isError` is true.

#### [GAP-02] Silent Mutation Failures in `useSessions.js`
- **Severity**: Medium — Session operations (create, rename, delete, add asset, remove asset, split, merge) provide no visual feedback on failure.
- **Location**:
  - `frontend_v2/src/hooks/useSessions.js:79-146`
- **Evidence**:
  Mutations in `useSessions.js` omitted `onError` callbacks. In `SessionPanel.jsx`, mutations caught errors and logged them only to `console.error` without user-visible notifications.
- **Proposed Fix**:
  Wire `onError: (error) => reportError('session action', error)` to all mutations in `useSessions.js` using `reportError` from `useWorldVaultResource.js`.

#### [GAP-03] `BatchStory.jsx` and `ImageToStory.jsx` API Response Mismatch & Navigation Failure
- **Severity**: Medium — Story variant selection attempts to call a non-existent `/api/v2/stories/from-variant` endpoint and accesses `resp.data` on client responses.
- **Location**:
  - `frontend_v2/src/pages/BatchStory.jsx:34, 62-67`
  - `frontend_v2/src/pages/ImageToStory.jsx:35`
- **Evidence**:
  `client.js` `api.post` returns the parsed response body directly. Accessing `resp.data` yields `undefined`. In `BatchStory.jsx`, `handleContinue` called `/api/v2/stories/from-variant`, which does not exist on the backend.
- **Proposed Fix**:
  Correct response access to `resp` (or `resp.data || resp`). Update `BatchStory.jsx:handleContinue` to use the standard story creation workflow (`/api/v2/stories` and `/api/v2/stories/{story_id}/chapters`).

### Tech Debt and Duplication

#### [DEBT-01] Swallowed Exceptions in Catalog Checkpoint Recommendations
- **Severity**: Low — Silent exception catching obscures database or schema errors.
- **Location**:
  - `backend_v2/api/routes/models/crud.py:82-83`
  - `backend_v2/api/routes/world_vault/llm_config.py:88-89`
- **Evidence**:

- **Proposed Fix**:

#### [DEBT-03] Synchronous Avatar File I/O in Character Import and Duplicate Routes
- **Severity**: Low — Event loop blocked during avatar file operations.
- **Location**:
  - `backend_v2/api/routes/world_vault/characters.py:876-880, 1311-1314`
- **Evidence**:
  `import_character` and `duplicate_character` execute synchronous `with open(...)` and `shutil.copy2(...)` directly on the event loop.
