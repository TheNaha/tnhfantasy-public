### Critical Bugs & High-Risk Defects

#### B-01: Sync filesystem I/O blocks the async event loop in two route handlers
- **Severity**: High — blocks the event loop on every request, hurting latency and concurrency under load
- **Location**:
  - `backend_v2/api/routes/interrogate.py:127` `os.path.exists(path)` and `:129` `open(path,"rb")`/`f.read()` inside `async def interrogate_image`
  - `backend_v2/api/routes/world_vault/locations.py:183` `os.makedirs(...)` and `:186-187` `open(...,"wb")`/`buffer.write(content)` inside `async def upload_location_image`
- **Evidence**: Both handlers are `async def` but perform blocking disk I/O directly on the event loop without `asyncio.to_thread`. Confirmed by reading the code; neighboring routes (`files.py`, `settings.py`, `llm_config.py`) correctly wrap blocking calls in `asyncio.to_thread`.
- **Proposed Fix**: Wrap the blocking sections in `asyncio.to_thread`.
- **Status**: fixed

#### B-02: Silent exception swallow in `ProviderTelemetryService.forget_provider`
- **Severity**: Medium — hides `forget_probe()` failures during provider deletion; consistent with the pattern fixed in DEBT-01 (workflow_builder.py/lifecycle.py) but this site was missed
- **Location**: `backend_v2/services/provider_telemetry_service.py:420-425` (`except Exception: pass`)
- **Evidence**: `forget_provider()` catches every exception from `forget_probe(provider_id)` with a bare `pass`, so a real probe-teardown failure is invisible. Other candidate "swallow" sites (`provider_status_service.py:337-343`, `job_queue.py:365-368`, `provider_deploy.py:331-349`) were verified as intentional graceful degradation and left alone.
- **Proposed Fix**: Replace `pass` with a structured `logger.debug(...)` (matching DEBT-01 precedent), so the failure is observable but non-fatal.
- **Status**: fixed

#### B-03: Ad hoc `HTTPException` instead of `ComfyError` in `/api/ready`
- **Severity**: Medium — inconsistent error response shape vs the rest of the API (no machine-readable `code` field), contrary to AGENTS.md convention
- **Location**: `backend_v2/api/routes/health.py:31` `raise HTTPException(status_code=503, ...)`
- **Evidence**: `health.py:31` raises raw `HTTPException`. Everywhere else the codebase raises `ComfyError` subclasses (`ServiceUnavailableError` exists for 503) so the global handler emits `{code, message}`. Status code is unchanged (503); only the body gains consistency.
- **Proposed Fix**: Raise `ServiceUnavailableError("database unavailable")` instead.
- **Status**: fixed

### Duplication & Tech Debt

#### D-01: Inline empty-state markup duplicated instead of shared `<EmptyState>`
- **Severity**: Low/Medium — duplicated UI markup, no behavior bug, but ~7 hand-rolled empty states bypass the shared component
- **Location**: `frontend_v2/src/components/story/StoryContextPanel.jsx` (`:131`, `:177`, `:237`, `:298`, `:362`), `frontend_v2/src/components/chat/ChatSidebar.jsx:102`, `frontend_v2/src/components/chat/NewChatModal.jsx:272`
- **Evidence**: Shared component `frontend_v2/src/components/EmptyState.jsx` exists and is used by 7 other pages. The 7 sites above render their own icon + "No …" text conditionally.
- **Proposed Fix**: Replace each with `<EmptyState ... />`.
- **Why not applied**: `EmptyState` calls `useNavigate()` at render (line 157) and requires Router context. Adding it to `ChatSidebar`/`NewChatModal` (which render without a Router in their unit tests) broke 10 tests across `ChatSidebar.test.jsx` and `NewChatModal.test.jsx`. Fixing those tests is legitimate but is test churn for a cosmetic change, so it is deferred.
- **Status**: flagged (deferred — low-value cosmetics, not a bug fix)

#### D-02: `jobs_cleanup` config has zero production consumers
- **Severity**: Medium — `jobs_cleanup` (max_age_hours/auto_cleanup/cleanup_interval) is defined in `config.py`, validated, exposed in settings, and tested, but `get_jobs_cleanup_max_age/auto/interval` are never called outside `config.py`/`settings.py`/tests
- **Location**: `backend_v2/config.py:176,884,1046-1052,1424-1436`; `api/routes/settings.py:264-284,567`; `tests/test_config.py:410-417`
- **Evidence**: Grep across `backend_v2` shows no caller of the three getter functions in routes/services/jobs. The cleanup feature is configured but never scheduled.
- **Proposed Fix**: FLAG — implementing a scheduled job-cleanup task is new behavior. `auto_cleanup` defaults `false`, so adding the machinery gated behind that flag is inert-by-default (no behavior change). Decide whether to implement in this pass or a future one.
- **Status**: flagged

### Integration Gaps

#### I-01: Frontend unhandled promise rejections in `ChatWorkspaceContext`
- **Severity**: Medium — `mutateAsync` calls without `try/catch` can produce unhandled promise rejections (crash the page/session in strict environments)
- **Location**: `frontend_v2/src/contexts/ChatWorkspaceContext.jsx:405`, `:848`
- **Evidence**: `mutateAsync(...)` is awaited with no surrounding `try/catch`; a rejected mutation propagates as an unhandled rejection.
- **Proposed Fix**: Wrap each in `try/catch` that surfaces the error through the existing error state (matching surrounding patterns).
- **Status**: fixed
