## 2. Detailed Findings

### [CRIT-01] Migration 112 Crash on Fresh / Partial Databases
- **Location**: `backend_v2/infrastructure/migrations/steps.py:2117` (`_migration_112_download_progress_tracking`)
- **Impact**: Database initialization or partial database migrations crashed with `RuntimeError: Migration step 112_download_progress_tracking failed: provider_version_status`.
- **Root Cause**: The step unconditionally inspected columns and attempted `ALTER TABLE provider_version_status ADD COLUMN ...` without verifying table existence via `inspector.get_table_names()`. In SQLite unit tests (such as `test_run_migrations` in `test_database.py`), the test database only creates the `jobs` table, raising `NoSuchTableError`.
- **Remediation**: Added guard checking table presence:
  ```python
  inspector = inspect(conn)
  if "provider_version_status" not in inspector.get_table_names():
      return False
  ```
  Returning `False` cleanly skips the migration on databases where the table is not present.

### [CRIT-02] In-Process Model Download Skipped via TypeError
- **Location**: `backend_v2/infrastructure/repositories/model_repo_v2.py:1016` (`ModelRepositoryV2.update_provider_status`)
- **Impact**: All in-process model downloads were skipped silently during reconciliation; models remained missing on workers.
- **Root Cause**: Commit `7c236f4f` updated `_mark_download_start` in `in_process_reconciliation.py` to pass `bytes_downloaded=0, download_speed=None, eta_seconds=None` through `_write_provider_status` into `update_provider_status`. However, `update_provider_status` did not accept those parameters and lacked `**kwargs`, causing a `TypeError`. Because `asyncio.gather(..., return_exceptions=True)` was used, the exception was swallowed silently and download execution halted before `engine.download_file()` was ever invoked.
- **Remediation**: Updated `ModelRepositoryV2.update_provider_status` signature to accept `bytes_downloaded: int | None = None, download_speed: float | None = None, eta_seconds: int | None = None`, and persisted these fields to `ProviderVersionStatus` records.

### [CRIT-03] Model Download Failure Never Transitioned to `failed`
- **Location**: `backend_v2/services/in_process_reconciliation.py:705` (`_run_reconciliation`)
- **Impact**: Failed model downloads never transitioned status to `failed` in the database, leaving models stuck in `downloading` or `pending`.
- **Root Cause**: Commit `7c236f4f` placed `engine.download_file()` inside a `try/finally` block for progress monitor task cancellation, but disconnected it from the `except Exception as exc:` block handling `stats["downloads_failed"]` and `_mark_failed`.
- **Remediation**: Re-enclosed `engine.download_file()` and download finalization within the `try/except Exception as exc:` handler that records `status="failed"`, logs errors, updates stats, and emits status events.

### [CRIT-04] Broken Import Path in Onboarding Wizard
- **Location**: `frontend_v2/src/components/onboarding/OnboardingWizard.jsx:15`
- **Impact**: Component failed to compile; tests failed to load.
- **Root Cause**: Import statement referenced `../constants/queryKeys`, which resolved to non-existent `src/components/constants/queryKeys`.
- **Remediation**: Corrected import path to `../../constants/queryKeys`.

### [GAP-01] Query-Derived Empty States Ungated by Query Errors
- **Location**: `frontend_v2/src/pages/WorldMap.jsx:131` and `frontend_v2/src/pages/RelationshipTimeline.jsx:99`
- **Impact**: Violates strict UI invariant: when network requests fail (503 / 500 / offline), empty state UI ("No locations yet" / "No characters yet") was rendered instead of error states, misleading users into believing data was empty rather than failed.
- **Root Cause**: Pages rendered `<EmptyState>` when `worldLocations.length === 0` or `characters.length === 0` without checking `isError`.
- **Remediation**:
  - `WorldMap.jsx`: Destructured `isError, error, refetch` from `useLocations()`, rendering `<QueryErrorState noun="locations" error={error} onRetry={refetch} />` when `isError` is true.
  - `RelationshipTimeline.jsx`: Destructured `isError, error, refetch` from `useCharacters()` and `useChats()`, rendering `<QueryErrorState noun="characters" error={charsErr || chatsErr} onRetry={() => { refetchChars(); refetchChats(); }} />` when either query errors.

### [GAP-02] App Boot Smoke Route Count Assertion Out of Date
- **Location**: `backend_v2/tests/test_app_boot_smoke.py:538`
- **Impact**: Boot smoke test failed on valid application startup.
- **Root Cause**: Commit `51921568` intentionally added 3 new API endpoints:
  1. `GET /api/v2/world-vault/onboarding/templates`
  2. `POST /api/v2/stories/image-to-story`
  3. `POST /api/v2/stories/batch-generate`
  This increased route paths from 295 to 298 and operations from 383 to 386.
- **Remediation**: Updated smoke test assertions to `len(spec["paths"]) == 298` and `sum(len(ops) for ops in spec["paths"].values()) == 386`.

### Tech Debt / Duplication & Architecture / Performance Notes
- **WebSocket Reconnection & Heartbeats**: Commit `7c236f4f` increased pingTimeout to 120s to prevent background browser tab freezing. Heartbeat handling remains healthy.
- **Reconciliation Concurrency**: In-process reconciliation uses per-provider semaphores and active lock tracking.
- **Empty State Invariant System**: Invariant tests in `queryErrorInvariants.test.jsx` enforce that any query-derived empty state is guarded against query failure. This test suite now passes 100%.

### Optional Improvements (For Future Decision)
1. **Toast Error Consolidation**: Consolidate error toasts between WebSocket disconnected banners and query error toasts to avoid double-toasting on transient network drops.
2. **Character Avatar Caching**: In `RelationshipTimeline.jsx`, character avatar lookups repeat `characters.find()` per message bubble; memoizing an `id -> character` Map improves performance for long chat histories.
