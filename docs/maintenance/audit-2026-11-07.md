## New findings

### Critical Bugs

#### [B-NEW-01] Avatar upload routes perform blocking file I/O on the event loop
**Severity:** Medium — blocks the event loop for the duration of a disk write on every avatar upload
**Location:**
- `backend_v2/api/routes/world_vault/agents.py:303` (pre-fix: `with open(avatar_path, "wb")` inside `async def upload_agent_avatar`)
- `backend_v2/api/routes/world_vault/characters.py:1109` (pre-fix: `with open(avatar_path, "wb")` inside `async def upload_avatar`)
**Evidence:** `locations.py:192` and `characters.py:1109` (post-fix) already wrap the write in `asyncio.to_thread`; the agents route and the characters route's makedirs+write were left synchronous. `agents.py` additionally performed `session.commit()` synchronously in the async route.
**Fix:** Wrapped the makedirs+write (and, for agents, the session commit) in `asyncio.to_thread`, mirroring the characters route. Added `import asyncio` to agents.py. Public API unchanged.
**Status:** Fixed.

#### [B-NEW-02] WorldMap ignores worlds-query failure
**Severity:** Low — a failed worlds query leaves an empty map with no retry affordance
**Location:** `frontend_v2/src/pages/WorldMap.jsx` (pre-fix: only `useLocations` error surfaced)
**Fix:** Destructure `isError`/`error`/`refetch` from `useWorlds()` and render `QueryErrorState` when either query fails.
**Status:** Fixed.
