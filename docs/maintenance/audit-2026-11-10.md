## Critical bugs (verified)

### [B1] Migration `092` never adds the `story_chapter_revisions.beats` column
**Severity:** Medium — a `restore_chapter_revision` rewind leaves `beats` behind, so chapter state is not fully rewound.  
**Location:** `backend_v2/infrastructure/migrations/steps.py:2421-2428`  
**Evidence:** `_migration_092_revisions_carry_beats` logs "column_added" and returns `True` when `beats` is absent, but the `ALTER TABLE ... ADD COLUMN beats` statement (lines 2424-2426) is unreachable dead code — it sits after `return True` inside the `if "beats" in cols:` branch. So the column is never added on upgraded databases.  
**Fix:** Dedent the `conn.execute(...)` to function-body level so it runs when the column is absent.

### [B2] Migration `070` re-executes on every startup
**Severity:** Low — wasted work on every boot; step never recorded when nothing changed.  
**Location:** `backend_v2/infrastructure/migrations/steps.py:2865`  
**Evidence:** The step's own NOTE (lines 2787-2794) states it must deliberately return `True` so `run_migrations` records it and it never re-runs. It currently returns `changed`, which is `False` when tables/index already exist, so it re-runs every boot (idempotent `CREATE ... IF NOT EXISTS`, so no corruption, just wasted work).  
**Fix:** `return True` unconditionally, matching the documented intent.
