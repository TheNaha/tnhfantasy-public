### Critical Bugs

#### [F-01] Character mutations in `useCharacters.js` surface no errors — failures are silent
**Severity:** High — a failed create/update/patch/delete/import gives the user no feedback; the UI optimistically invalidates nothing on error
**Location:** `frontend_v2/src/hooks/useCharacters.js`
**Evidence:** Every mutation (`useCreateCharacter:37`, `useUpdateCharacter:48`, `usePatchCharacter:60`, `useUploadAvatar:75`, `useReorderCharacters:93`, `useDeleteCharacter:104`, `useImportCharacterCard:115`, `useCommitCharacterCard:211`, `useCloneCharacter:234`, `useAnimateCharacterAvatar:265`) declares only `onSuccess`. The shared vault pattern in `services/...`/`hooks/useWorldVaultResource.js` (`useCreateResource`, `useUpdateResource`, `useDeleteResource`) all attach `onError: (error) => reportError(action, error)` so failures toast. `reportError` is module-private (not exported). `useCharacters.js` imports `invalidateVaultAggregates` from that module but never reuses its error handling.
**Fix:** Exported `reportError` from `useWorldVaultResource.js` and added `onError: (error) => reportError('<action>', error)` to every character mutation (`useCreateCharacter`, `useUpdateCharacter`, `usePatchCharacter`, `useUploadAvatar`, `useReorderCharacters`, `useDeleteCharacter`, `useImportCharacterCard`, `useCommitCharacterCard`, `useCloneCharacter`, `useAnimateCharacterAvatar`). Public API unchanged; purely additive.
**Status:** Fixed — committed on `maintenance/pass-2026-11-06`. Verified: `eslint` clean, `useCharacters.test.js` 9/9 passed.

### New Findings

#### Critical Bugs

##### [CRIT-01] Optimistic mutation error handlers silently roll back without user notification
- **Severity**: High
- **Location**:
  - `frontend_v2/src/hooks/useStories.js:165-169, 253-257, 279-283, 299-303, 421-425`
  - `frontend_v2/src/hooks/useChats.js:300-303`
  - `frontend_v2/src/hooks/useMessages.js:37-41, 62-66`
- **Evidence**:
  `frontend_v2/src/App.jsx:281-285` configures `MutationCache`:
  ```javascript
  if (typeof mutation.options.onError === 'function') return;
  toast.error(error?.message || 'Request failed', { id: 'mutation-error' });
  ```
  Whenever a mutation declares `onError`, the global error toast is bypassed. In `useStories.js`, `useChats.js`, and `useMessages.js`, optimistic mutations define `onError` solely to restore cache (`context.previous`), but never emit a toast notification. On network or server failure, edits and messages silently vanish without any indication to the user.
- **Fix**: Add user feedback toast (`toast.error(error?.message || 'Action failed')`) inside these rollback `onError` callbacks.

##### [CRIT-02] `create_location` silently drops `map_x` and `map_y` coordinates
- **Severity**: High (Data Loss)
- **Location**: `backend_v2/api/routes/world_vault/locations.py:37-38, 77-84`
- **Evidence**:
  `LocationCreate` defines `map_x: float | None = None` and `map_y: float | None = None`, but `create_location` initializes `Location(...)` omitting both attributes entirely, discarding coordinates submitted by callers during creation.
- **Fix**: Add `map_x=location_in.map_x` and `map_y=location_in.map_y` to the `Location` instantiation in `create_location`.

##### [CRIT-03] Comic export blocking I/O, empty-page crash risk, un-offloaded sync `session.commit()`, and background task unhandled rollback
- **Severity**: High
- **Location**:
  - `backend_v2/services/comic_exporter.py:542, 650-654, 704-726`
  - `backend_v2/api/routes/world_vault/stories.py:2980-2995`
- **Evidence**:
  1. `_write_html_reader` in `comic_exporter.py:542` accesses `page_paths[0]` directly without checking `if not page_paths:`, causing an `IndexError` if page list is empty.
  2. `export_comic_chapter` is an `async def` function that runs synchronous PIL fallback generation, synchronous `json.dump`, and synchronous `zipfile.ZipFile` archive compression directly on the event loop.
  3. Line 726 calls `session.commit()` synchronously instead of `await asyncio.to_thread(session.commit)`.
  4. `_run_export` in `stories.py:2980-2995` catches exceptions but does not execute `await asyncio.to_thread(task_session.rollback)` prior to attempting `update_job(..., status=JobStatus.FAILED)`, leaving failed PostgreSQL transactions in an aborted state that crashes status recording.
- **Fix**:
  Guard `page_paths[0]` in `_write_html_reader`; offload page assembly, manifest, CBZ writing, and HTML generation to `asyncio.to_thread`; offload `session.commit()`; add `task_session.rollback()` in `_run_export` failure handler.

##### [CRIT-04] `CredentialsTab.jsx` delete mutation has no `onError` handler / unhandled rejection
- **Severity**: Medium-High
- **Location**: `frontend_v2/src/components/providers/tabs/CredentialsTab.jsx:132-138, 204-206`
- **Evidence**:
  `deleteMutation` declares only `onSuccess`, called directly via `deleteMutation.mutate({ key })` from an inline button `onClick`. If deletion fails, no feedback is displayed and the mutation error is unhandled.
- **Fix**: Add `onError: (e) => toast.error(e?.message || 'Failed to delete credential')` to `deleteMutation`.

#### Integration Gaps

##### [GAP-01] Deleting active collection leaves dangling `activeCollection` in Zustand & `localStorage`
- **Severity**: Medium
- **Location**: `frontend_v2/src/hooks/useCollections.js:114-124`, `frontend_v2/src/store/useStore.js:16-31`
- **Evidence**:
  When a user deletes a collection, `useDeleteCollection` invalidates query caches but never checks if `useStore.getState().activeCollection` matches the deleted collection's ID. The stale ID remains persisted in `localStorage`, leading to repeated 404 queries or broken UI selection.
- **Fix**: Reset `activeCollection` to `null` in `useDeleteCollection.onSuccess` if it matches the deleted ID.

##### [GAP-02] External model service errors (400, 404, 429) masked as 502 Bad Gateway
