# Code audit — 2026-10-05

Supersedes `audit-2026-10-04b.md` for everything it marks **fixed**. Everything

## How this pass was run

Six read-only auditors over disjoint scopes — backend core, frontend data layer,
frontend UI, provider tier, cross-seam contract, and performance/DB/delivery —
plus a direct pass of my own against the **running stack**: every route crawled in
a real browser for console errors and failed requests, every hot endpoint timed,
and the two busiest code paths profiled in-process against live Postgres.

Every finding below was reproduced before it was written down, and every fix
ships with a test that was confirmed to **fail when the fix was reverted**. Four
sub-agent claims did not survive that check and are listed under
[Corrections](#corrections-to-previous-and-this-passs-findings) rather than
quietly dropped.

Baseline before any change: backend 3054 passed / 9 skipped, provider 1013
passed / 5 skipped, frontend 1604 passed, `ruff` clean, eslint 0 errors / 6 known
warnings, production build 756 kB raw / 198 kB gzip in the eager set.

After: backend 3095 passed / 9 skipped, provider 1025 passed / 5 skipped,
frontend 1608 passed, `ruff` clean, eslint unchanged, build unchanged. A crawl of
all 30 routes in a real browser now reports **28 of 30 completely clean**, against
0 of 30 at baseline — every route was paying the 307 described above.

## Fixed in this pass

### P0/P1 — data loss

**The provider tier was deleting user files, unattended, on a timer.**
`remote_agent/server.py:427`, `image_worker/engines/beam/beam_app.py:605`,
`image_worker/engines/modal/modal_app.py:1077`.

`models/embeddings`, `models/wildcards` and `models/poses` are all in
`MODEL_DIRECTORIES`, so the reconciliation validator walks them — and it runs with
`delete_invalid=True` every couple of hours, unattended, against the operator's
real volume. Those directories are *supposed* to hold non-model files: `.txt`
embeddings and wildcard lists, `.yaml` pose configs.

`validate_downloaded_file` skips its header check for those extensions but still
applies `MIN_MODEL_SIZE` (10 KiB), so an ordinary 200-byte wildcard list came back
`valid: False, indeterminate: False` — a definite verdict, and the only kind the
delete branch acts on. Reproduced on the remote agent, one `models/wildcards`
sweep:

```
files before: big_prompt.yaml easynegative.txt large_wildcards.txt
              my_wildcards.txt style.yaml
total_invalid: 4
files after:  large_wildcards.txt
```

Only the file over 10 KiB survived. No undo, no notification; the operator finds
out when a prompt stops applying. All three sweeps guarded with `is_model_file`,
which only excludes pipeline-owned (`.lock`, `.downloading`) and sidecar names —
it was never going to stop a `.txt`.

**Fixed** by `is_model_candidate` in `provider_core/utils.py`, a delete guard that
also excludes `NON_MODEL_SUFFIXES`, with `validation._SKIP_HEADER_EXTENSIONS`
derived from that same tuple so the two answers cannot drift. Guarded by
`tests/test_delete_sweep_preserves_non_models.py`, which asserts the rule against
the real sweep implementation and fails when the guard is removed.

### P1 — a cancelled LLM job was recorded as a success

`provider_core/sse.py:123`, reached from all three LLM engines
(`openai_compat/client.py:179`, `anthropic/client.py:226`,
`google/client.py:271`).

`iter_sse_data` runs one cancellation probe per SSE frame and, on a hit, called
`await on_cancelled()` — discarding the return value. Every engine implements that
callback as a coroutine that *builds* the frame:

```python
async def _cancelled() -> str:
    return TaskEvent(event="cancelled", job_id=job_id,
                     outputs=[{"role": "assistant", "content": full_content,
                               "cancelled": True}]).to_ndjson()
```

So the frame was constructed and dropped, the engine's `async for` simply ended,
and control fell through to the post-loop `yield TaskEvent(event="completed")`.
The backend decides success from `outputs[0]["cancelled"]`
(`services/provider_client.py`), a key the completed frame does not carry — so
the job landed SUCCESS with a half-written assistant message committed to the
chat. Measured: events `['delta', 'delta', 'completed']`, content `"I love "`.

**Fixed** with `SSECancelled`, a distinct yielded type. A bare string would not
have worked: the engines parse each frame as a vendor payload, and a `cancelled`
TaskEvent has no `choices`, so it would have been skipped one layer down and
reproduced the same fall-through. Three assertions in `test_sse_framing.py` pinned
the discard (`assert out == []`); they now assert no vendor frame is yielded and
exactly one marker is.

### P1 — a chat turn could cost 2.5× the context budget

`services/context_builder.py:410` (`prune_context`).

The oversized-message trimmer only considered messages *individually* above
`TRUNCATION_MIN_TOKENS`, while the message-dropping loop stops at
`MIN_UNPINNED_MESSAGES = 2`. A set of mid-size turns whose **sum** overflowed
matched no candidate, the loop gave up, and the oversized prompt went to a paid
provider — silently, with no `conversation_truncated` line. Measured:

```
2 x 5,250-token turns against a 4,096 budget -> 10,503 tokens out (2.56x)
3 x 3,000-token turns                          ->  6,003 tokens out (1.47x)
2 x 2,100-token turns (sum just over)          ->  4,200 tokens out (1.02x)
```

**Fixed** with two gated passes: the conservative one first, so an ordinary turn
the caller asks for still survives whole, then an escalation with no size floor.
All seven over-budget shapes now land within budget; the two shapes that must not
be trimmed (under-budget conversations, a budget large enough for the content)
are untouched. Two details the first attempt got wrong, caught by the existing
tests: the truncation marker has to be stripped before re-measuring or it stacks,
and a budget too small to afford `MIN_RETAINED_TOKENS` per message now declines
and logs instead of leaving each kept message one character long.

### P1 — three API paths paid a 307 on every request

Measured on the running stack: `GET /api/v2/providers` answered `307 Temporary
Redirect` with `Location: /api/v2/providers/`. FastAPI does not 404 an unslashed
collection path — it redirects and re-issues, so every such call costs an extra
round trip and a redirect body to parse and discard. `list` is app-wide (the
layout status dot mounts `useProvidersPageData`), so this was **two extra round
trips on every page navigation in the product**. Same for
`/api/v2/models/` and the three `/api/v2/world-vault/graph-layout` verbs.

**Fixed** by naming the canonical paths, and guarded by
`src/test/apiPathInvariants.test.js`, which reads every literal `/api/...` string
out of the source and fails if adding a slash would reach one of the three routes
the backend serves that way.

## Still open

### 1. Five endpoints return the same 1.5 MB of models, and none has a caller

Measured on the running stack:

| endpoint | bytes | ms | frontend caller |
|---|---|---|---|
| `GET /api/v2/models/` | 1,518,293 | 1131 | none |
| `GET /api/v2/models/cache` | 1,518,293 | 855 | none |
| `GET /api/v2/providers/model-cache` | 1,518,293 | 855 | none (byte-identical to the above) |
| `GET /api/v2/models/all` | 1,518,215 | 918 | none |
| `GET /api/v2/models/search` (no `q`) | 1,518,215 | 1078 | none |

16 concurrent requests to `/api/v2/models/` take **19.1 s** wall (0.8 req/s)
against 65.5 req/s for `/api/live`. It is **not** an event-loop block — p50
`/api/live` is 22 ms while 8 requests are in flight — it is ORM row
materialisation: in-process against live Postgres, `get_all_models()` is 26 ms
but the five bulk loaders inside `models_to_dict` cost 56 / 24 / 19 / 93 /
**411** ms, with `_bulk_load_provider_statuses_by_model` dominating on a
1,577-row table whose indexes are all present.

`/api/v2/models/search` with no `q` is the sharp edge: one unauthenticated `GET`
returns the whole model table, and the stack has no authentication.

**Decision needed:** collapse to one endpoint, or keep four aliases for external
callers. They are three separate implementations today.

### 2. The statistics cache stampedes on every cold key (P1 — FIXED)

`infrastructure/cache.py` decorated functions with check-then-compute-then-store
and nothing in between, so N concurrent misses all missed and all ran the whole
aggregation. Measured on `/api/statistics/detailed` against live Postgres:

```
one cold request                 10.9 s
eight concurrent cold requests   58-71 s EACH
the same key afterwards          0.0008 s
```

The stampede did not make eight answers cheaper — it made every one of them about
six times slower than the single request that would have populated the key. The
handler is `async def` calling `asyncio.to_thread`, so all eight land in the
thread pool together and compete for the same connections.

**Fixed** with one `asyncio.Lock` per (cache, key), removed once the result is
stored. Waiters re-check inside the lock, so exactly one computation runs per key
and distinct keys still run concurrently.
`tests/test_cache_single_flight.py` counts the wrapped function's own
invocations, so the assertion is about what happened rather than about elapsed
time, and covers the leak (a raising computation must not poison the key).

### 16. Nine migration versions are unrecorded in the live database (P3)

`002, 004, 005, 045, 054, 056, 059, 081` are declared in
`infrastructure/migrations/steps.py` and absent from `schema_migrations`, because
`SQLModel.metadata.create_all` runs immediately before the steps runner and
creates the object the step was going to create — so the step returns `False` and
the runner never records it. Those steps therefore re-run on every boot. On
migrations 066–068 the re-run work is a full-table jsonb-extracting `UPDATE` over
`assets` (16,907 rows here), which is why they *do* record on deployments where
`create_all` had not already made the column and do not on fresh installs.

Measured boot cost on this deployment: **~1 s** for the whole migration phase, so
this is structural debt rather than an urgent cost. The fix is for a step to
record its version when its work ran, not only when it changed something.

### 26. `resolve_default_checkpoint`'s "unset" option can never succeed (P2)

`components/Settings` Generator panel offers
`<option value="">{'(unset — backend falls back to its compiled-in default)'}</option>`
and sends `{generator: {default_checkpoint: ''}}`. `config._validate_config` calls
`_check_str(...)` without `allow_blank`, which raises on an empty string:

```
default_checkpoint='':       REJECTED -> generator.default_checkpoint must not be blank
default_checkpoint=None:     accepted
```

So the control whose label promises "unset" always fails with
`Rejected: generator.default_checkpoint must not be blank`. The backend is right —
blank is rejected deliberately and pinned by `test_settings_exposure.py:303`, and
`resolve_default_checkpoint` treats `""` as "fall back". The honest fix is a way to
express *delete this key*, which `_deep_merge` cannot currently do because the
route's `exclude_none=True` strips a `None` leaf before the merge ever sees it.
Worth noting the same route answers "Settings updated successfully" for a payload
whose only leaf is `None`, because `exclude_none` empties the section.

## Database, delivery and event-loop findings (measured)

### 29. The event-loop guard cannot see the code it is guarding (P1)

`tests/test_event_loop_invariant.py` indexes call-graph nodes by **bare function
name**. Twenty-three names collide across modules, and `_chain_has_real_await`
returns `True` as soon as *any* colliding definition awaits — so two live `async
def` routes pass the guard only because of a namesake elsewhere:

```
lifecycle.py:519 cleanup_orphaned_provider_statuses  verdict_now=True  without_collisions=False
lifecycle.py:555 cleanup_provider_state               verdict_now=True  without_collisions=False
```

Eleven live off-register routes await one of the colliding names. The register
itself is otherwise accurate: **0 offenders outside `SYNC_CHAINED` ∪
`AWAIT_CHAINED_TO_SYNC_SERVICE`** (34 + 11 = 45), all four `SEARCH_DIRS` exist,
and an AST scan found **0** direct sync `session.*` calls in `async def` route
handlers. This is the same shape as every other guard in the codebase that
records intent in a comment: a guard that cannot see the code is not a guard.

Fix: key the index on `module.qualname`, and make an unresolvable callee a
failure rather than a pass.

### 30. `/api/files?sort=name_asc` loads the whole table (P1)

`api/routes/files.py:691-698` materialises all 16,518 live asset rows —
including the 3.2 kB average `metadata_` jsonb — and sorts in Python.

```
sort=date_desc  0.023 s
sort=name_asc   6.649 / 6.454 / 9.267 / 10.245 s
docker stats    435.5 MiB -> 575.2 MiB during the call
```

`total = len(rows)` is only consulted because the page is sliced in memory. The
call runs on `asyncio.to_thread`, so N requests multiply. UI reachability is
narrow today (`ModelSelector`/`InstalledTab` send `name_asc` with
`directory=models/*`, which takes the `model_service` branch) but the endpoint is
unauthenticated and the cost is per-request.

### 35. Preflight's network-exposure check cannot be triggered (P3 — FIXED)
