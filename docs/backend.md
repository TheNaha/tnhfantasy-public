# Backend Documentation

The backend of TNHComfy (`tnhcomfy-backend`) is built with **FastAPI** (Python), serving as the core engine for job queuing, orchestration, and communication between the frontend and serverless inference providers.

## Key Technologies
- **FastAPI:** High-performance web framework for APIs.
- **SQLite:** Lightweight local database for job tracking and state management (`backend_v2/data/comfy.db`).
- **WebSockets:** Real-time bi-directional communication with the frontend for job status updates (Socket.IO).
- **HTTPX:** Asynchronous HTTP client used for non-blocking requests to external providers.
- **Structlog:** Structured logging for better debugging and observability.
- **Prometheus:** Metrics exposed at `/metrics` via `prometheus_client`.
- **Tenacity:** Retry with exponential backoff for provider calls.

## Architecture

The backend consists of several key modules:
1. **API Routes (`backend_v2/api/routes`):** Defines the REST endpoints for jobs, models, providers, collections, generation, settings, statistics, and WebSockets.
2. **API Infrastructure (`backend_v2/api/`):** App setup, dependency injection (`deps.py`), error handlers, job orchestration, job processing, lifecycle management, and provider client.
3. **Services (`backend_v2/services/`):** Business logic including job queue, job service, load balancer, provider service, container manager, image service, model service, gallery indexer, and provider lifecycle management.
4. **Core (`backend_v2/core/`):** Domain entities (`entities.py`), domain events (`events.py`), domain exceptions (`exceptions.py`), DTOs, and workflow parser.
5. **Infrastructure (`backend_v2/infrastructure/`):** Database setup, migrations (`migrations/`), HTTP client, image processor, logging, metrics, request dedup, scheduler, background tasks, cache, model settings, parsers, and repositories.
6. **Provider Infrastructure (`backend_v2/infrastructure/providers/`):** Provider implementations (Modal, Beam), provider registry, NDJSON streaming parser, and provider configuration.

## Data Storage Strategy
- **Relational Data:** Information like jobs, models, and application settings are stored in `comfy.db` (SQLite, WAL mode).
- **Files:** Output images generated by ComfyUI are stored locally on the filesystem (partitioned as `output/{user_id}/{workspace}/YYYY/MM/DD/`). An `assets` DB table is maintained by `services/asset_reconciler.py` (thumbnail generation, blurhash, metadata extraction) and serves as the single source of truth for gallery listing, thumbnail serving, and statistics — no filesystem scans at startup.
- **Transient Data:** The backend does *not* permanently store large checkpoints. This ensures a lightweight and responsive server.

## Event Loop and Async Operations
- The backend relies heavily on `asyncio` to prevent blocking operations, specifically when fetching data from external APIs or performing database queries.
- **Synchronous Calls:** Any synchronous calls (like `requests.get()`) are generally avoided or refactored into `httpx.AsyncClient` calls.

## Development Setup
1. Ensure Python 3.13+ is installed (CI runs 3.13).
2. Navigate to `backend_v2`:
   ```bash
   cd backend_v2
   python3 -m venv venv
   source venv/bin/activate
   pip install -r requirements.txt
   ```
3. Copy `.env.example` to `.env` and fill in necessary tokens (HF_TOKEN, CIVITAI_TOKEN).
4. Run the server:
   ```bash
   uvicorn api.main:app --host 0.0.0.0 --port 8002 --reload
   ```

## Migrations
Migrations are manual and live in `infrastructure/migrations/` (tracked via a `schema_migrations` table). Do not introduce Alembic unless explicitly requested.

## Background Tasks
The backend completes image jobs in the background (thumbnail generation + blurhash + `assets` row upsert via `asset_reconciler.reconcile_asset`) before transitioning to `COMPLETED`, ensuring the gallery is always consistent and the frontend never fetches unindexed thumbnails.
